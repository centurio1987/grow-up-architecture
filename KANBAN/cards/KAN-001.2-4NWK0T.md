# KAN-001.2-4NWK0T — authoring-kit 정착

## 전략
<!-- 왜 이 접근인가 · 제약 · 버린 대안. 사람이 자유롭게 편집한다. -->
**루트 요청서 인용**: "authoring-kit를 적용하고, "~/code_test"의 집필 가이드를 계승해라."

**계승하는 것은 구조다.** code_test의 규율 — "집필 규칙의 정본은 플러그인이다. 규칙을 스킬 문서에 다시 쓰지 않는다. 플러그인 없으면 명확히 실패한다" — 를 그대로 가져온다. 3층: L0 공통 원칙과 L1 voice(`ppangtolab-teacher`)는 전역 `~/.claude/authoring/`에 이미 있고, 이 카드가 만드는 것은 L2 spec 2종(`gof-guide` · `analysis-guide`)과 프로젝트 바인딩(`paths.json` · `authoring.lock.json`), 그리고 게이트·검사기·렌더러·진입 스킬이다. 골격·문체 규칙은 spec/voice에만 두고 SKILL.md는 "어느 spec으로 쓸지 고르고 `authoring-write`에 넘기는 일"만 한다.

**옮길 수 없어서 새로 만드는 것**: 이해 게이트(`comprehension-gate.sh`는 code_test 프로젝트 안에만 있고 질문·FAIL 기준이 알고리즘 전제 — 복사한 뒤 Q1/Q3/Q5의 질문과 판정 문구를 함께 교체) · 외부 검토 축(`review-axes/guide.md`는 알고리즘용 — `scripts/review-axes-pattern.md` 신설: 패턴 정의의 정확성 · 비교의 타당성 · 구현과 설명의 일치 · DDD 일관성. fallback 없음) · 코드 검사기(`scripts/check-guides.py`) · HTML 렌더러(`scripts/render-guides.py`).

**spec 2개인 이유·새 골격·코드 검사 계약·HTML 계약**은 루트 카드 `KANBAN/cards/KAN-001-YXTC2C.md` 「전략」 절의 결정 1·2·10·11이 정본이다 — 여기 다시 쓰지 않는다. spec 작성은 `authoring-spec` 스킬의 역추출(기존 `template.md`·가이드 2편)로 시작하고, `{중괄호}` 레거시 표기는 `placeholders.legacy_accept`로 받는다. `principles.axis`는 structure/scope-principle/evidence만(`tech-deepdive`의 comprehension 축을 복사하면 validate가 막는다).

**lock 규율**: S1에서 처음 생성(파일이 없으면 `lock`이 만든다). 이후 검증에서 `lock`은 검사만 하고, `--update`는 규약 개정 시점(.3 S4)에서만 사유와 함께 커밋한다.

**analyzer 계약**: `디자인 패턴을 충족하는 최소 조건` 헤딩 문자열은 유지하고 레벨만 `###`. analyzer SKILL.md의 경로("프로젝트 루트" → `pattern-guide/design-pattern-guide/`)·헤딩 레벨·"첫 3개 필수" 규칙(→ `[필수]/[선택]` 표기)을 고치고 회귀 4건으로 검증한다.

**`.agents/skills`**: `.claude/skills`의 바이트 동일 사본. 어떤 도구가 읽는지 미확인이라 기본은 유지 + `diff -rq` 0을 검증에 둔다. 삭제/심링크는 유저 결정.

### 배치 2관점

- **단일 에이전트(순차)** — 배치: b1 S1–S3 / b2 S4–S6
- **오케스트레이션(병렬)** — 배치: b1은 **S1 → S2 → S3 순차**(lock 뒤에 spec, 공유 블록은 S2 소유·S3은 복사) / b2는 S4‖S5‖S6 폭 3 / 비고: 파일 소유권: S4 = `scripts/comprehension-gate.sh`·`scripts/review-axes-pattern.md`·`scripts/check-guides.py`, S5 = `.claude/skills/**`·`.agents/skills/**`, S6 = `scripts/render-guides.py`·렌더 자산. `paths.json`은 S1 소유이고 S4·S6이 키를 더할 때는 순차로

- [ ] `S6` `render-guides.py` HTML 렌더러 — 세 언어 펜스 → 탭(접근성 포함), mermaid 인라인 SVG, 링크 변환, 지문(md+렌더러+CSS+JS), 기존 가이드 1편 렌더 + `--derived` fresh

## 검증

`PLUGIN=~/.claude/plugins/cache/centurio87-plugins/authoring-kit/0.3.0`
```
python3 $PLUGIN/scripts/authoring.py status | python3 -c "import json,sys; d=json.load(sys.stdin); assert {'gof-guide','analysis-guide','kanban-report'} <= set(d['specs']), d['specs']"
python3 $PLUGIN/scripts/authoring.py lock                                   # 최신 (exit 0)
python3 $PLUGIN/scripts/authoring.py validate --all
python3 $PLUGIN/scripts/authoring.py resolve --voice ppangtolab-teacher --spec gof-guide --profile main --frozen
python3 $PLUGIN/scripts/authoring.py resolve --voice ppangtolab-teacher --spec analysis-guide --profile main --frozen
python3 scripts/check-guides.py --spec-shared
python3 scripts/check-guides.py --all pattern-guide/design-pattern-guide/singleton-pattern.md    # 구 골격이라 헤딩 불일치가 나와야 정상 — 검사기가 도는지만 본다
python3 scripts/check-guides.py --compile --self-test                       # 세 도구 버전 출력, 샘플 3블록 컴파일 0
bash scripts/comprehension-gate.sh pattern-guide/design-pattern-guide/singleton-pattern.md ; echo $?   # 0
bash scripts/comprehension-gate.sh <정당성 절 제거본> ; echo $?               # 3
grep -q 'comprehension_gate' .claude/authoring/paths.json
grep -q 'review-axes-pattern' .claude/authoring/specs/gof-guide/spec.json && grep -q 'review-axes-pattern' .claude/authoring/specs/analysis-guide/spec.json
python3 scripts/render-guides.py pattern-guide/design-pattern-guide/singleton-pattern.md && python3 scripts/check-guides.py --derived
grep -c 'pattern-guide/design-pattern-guide/' .claude/skills/design-pattern-analyzer/SKILL.md   # ≥ 1
grep -L 'mcp__cowork' .claude/skills/*/SKILL.md README.md                     # 셋 다 나와야 함(잔재 0)
diff -rq .claude/skills .agents/skills                                       # 0 (유지 결정 시)
```
