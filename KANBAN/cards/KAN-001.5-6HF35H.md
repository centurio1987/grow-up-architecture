# KAN-001.5-6HF35H — 분석 패턴 8편 재집필

## 전략
<!-- 왜 이 접근인가 · 제약 · 버린 대안. 사람이 자유롭게 편집한다. -->
**루트 요청서 인용**: "분석 패턴의 경우, 반드시 DDD 원칙을 준수해야 한다. 또한, 오해가 없도록, 구체적인 배경을 전제해야 한다. 예를 들어, transaction과 account 패턴을 설명할 때 entry는 transaction이 가지고 있을 수도 있고, account가 가질 수도 있으며 홀로 존재할 수도 있고, 혹은 별도 entity로 존재하나 account entity에 그에 대한 VO를 가지고 있을 수도 있다. 그래서 정확한 상황 설정이 중요하다."

**규칙은 여기 없다.** `.claude/authoring/specs/analysis-guide/`(.3 회고로 개정된 1.1)가 정본이다. 편마다 `상황 설정` MUST 표(bounded context / 불변식의 위치 / root·entity·VO 배정 / 타 aggregate 참조 방식)를 채우고 구현이 그 표와 1:1이어야 한다(aggregate 간 객체 참조 0). 리서치 입력은 `.1`의 `research/analysis-patterns.md`.

**회계 3편(Transaction · Posting Rule, 그리고 파일럿에서 쓴 Account)은 같은 배경 확정안**(`.1` S4 `research/accounting-context.md`, 유저 확정)을 인용하고, `### 상황이 달라지면` 절에 요청서가 든 Entry 4가지 소속을 표의 행으로 싣는다. 확정안 없이 쓰면 consideration 2편 중 하나와 반드시 모순이다 — 그래서 S1·S2가 앞이고, S3이 consideration 정합(문서1 정정/재명명 — 유저 결정, 문서2 frontmatter·링크, DDD README 심화 행)이다.

**나머지 6편**(Party · Accountability · Knowledge Level · Range · Measurement · Observation)은 값 객체·기반 추상 계열이다. 파일럿 Quantity의 실측 결과(MUST 표 처분)가 spec 1.1에 반영된 뒤에 쓴다. HTML은 여기서 그리지 않는다(.6에서 일괄).
