# KAN-002.1-7YT11M — system-design-guide 명세 등록 — 절 구성·작성법·검사 계약과 트랙 경로

## 전략
**입력**: 준비안 `pattern-guide/research/system-design-guide-plan-2026-11-13.md` 의 3절(한 편의 절 구성 표 · 절마다 지킬 규칙 · 기존 규약에서 가져올 것과 뺄 것)과 5절(정한 것 넷 — 구현 코드는 Java · TypeScript · Rust 세 언어가 같은 출력을 내는 기존 규약 유지, 위치 `pattern-guide/system-design-guide/<슬러그>/`, 명세 id `system-design-guide`, 파일럿 두 편). 기존 명세는 `gof-guide` 1.4.0 이다.

**절 이름은 뜻이 같으면 기존 것을 그대로 쓴다.** 검사기가 명세의 절 id 에 묶어 켜는 검사는 시나리오 검사(개수 · 단계 수)다(`scripts/check-guides.py:1086`, 커밋 `e2384dd` 기준 — 작업 트리의 검사기는 다른 작업이 고치는 중이라 줄 번호가 움직인다). 세 언어 컴파일 · 실행은 절 id 가 아니라 `### 구현` 헤딩 문구로 찾는다(`:133` · `:1289`). 그래서 시나리오 절은 기존 id `detail.scenario` 를, 구현 절은 기존 헤딩 문구 「구현」을 그대로 쓴다. 나머지 기존 id(`example.context` · `example.impl` · `example.realworld` · `selfcheck` · `refs`)는 검사 때문이 아니라 같은 뜻의 절을 두 계열에서 같은 이름으로 부르려고 물려받는다. 상황 설정 표 검사는 분석 패턴 트랙에서만 켜지므로(`:1071`) `example.context` 를 물려받아도 이 명세에는 걸리지 않는다. 요구사항 · 규모 추정 · 개념도 · 기술 상세 설명 · 대안 비교 · 요구 충족 확인 표만 새 id 를 쓴다.

**공유 블록에 합류하지 않는다.** `gof-guide` 와 `analysis-guide` 는 공통 규칙 덩어리를 바이트 단위로 같게 두고 `--spec-shared` 로 검사한다. 셋째 명세가 들어가면 규칙 하나를 고칠 때 세 파일을 함께 고쳐야 한다. 필요한 규칙은 출처 원칙 번호(PG 번호)를 달아 옮겨 적는다.

**문체(voice)는 기존 가이드와 같은 `ppangtolab-teacher` 다.** 캔버스는 기존 캔버스 옆(`.claude/skills/design-pattern-guide/system-design-guide-canvas.md`)에 둔다. 집필 진입을 기존 `design-pattern-guide` 스킬에 붙일지 새 스킬로 할지는 `KAN-002.2` 착수 때 정한다.

### 버린 대안

| 대안 | 버린 이유 |
| --- | --- |
| 공유 블록에 합류 | 바이트 동일 규약이 세 명세로 번져, 한 규칙을 고칠 때마다 세 파일을 고쳐야 한다 |
| 절 이름을 전부 새로 짓기 | 시나리오 검사는 절 id `detail.scenario` 에, 세 언어 검사는 헤딩 「구현」에 묶여 있어, 이름을 바꾸면 그 검사를 다시 만들거나 검사기를 고쳐야 한다 |
| `paths.json` 트랙 줄을 먼저 넣기 | 명세 없이 트랙만 있으면 그 폴더에 파일이 생기는 순간 검사기가 "spec 이 없습니다"로 멈춘다(`scripts/check-guides.py:368-371`, 커밋 `e2384dd` 기준) |

### 만약

| 만약 | 그러면 | 대응 |
| --- | --- | --- |
| 기존 검사가 새 명세의 절 구성과 맞지 않는다 | 시험 초안에서 엉뚱한 오류가 난다 | 검사기 변경은 이 카드 범위 밖이라 유저에게 묻고 별도 work 로 뺀다 |
| `paths.json` · `authoring.lock.json` 에 남아 있는 다른 작업의 미커밋 수정이 그대로다 | S4 커밋에 남의 수정이 섞인다 | S4 커밋 전에 그 수정이 커밋됐는지 보고, 아니면 처분을 유저에게 묻는다 |
| 명세를 더한 뒤 기존 37편의 검사 결과가 바뀐다 | 발행본이 조용히 실패로 바뀐다 | S4 에서 등록 전후의 `check-guides --all` 결과를 견주고, 다르면 등록을 되돌린다 |
