## 1. 작업 패키지
<!-- work 하나에 WP 하나. 각 WP 는 완료 기준으로 끝난다. -->
### WP1 · `S1` Specification — `gof-guide` 트랙

원전은 Evans·Fowler 공동 논문(`Specifications`, apsupp). 조합 가능한 술어를 객체로 만드는 패턴이라 구현 절 3언어가 그대로 선다.

**완료 기준**: `resolve --frozen` 통과 · 채점 PASS(라운드 ≤ 3, 자기 채점 금지) · `check-guides --all --compile --run` 0 · `gate-results.jsonl` 1줄 · HTML 렌더 + 도식 검사 통과.

**이 편에만 있는 요구 셋**
- `[필수]` 조건의 근거 괄호가 **apsupp 논문의 어느 절**인지까지 적는다(PG27). 원전이 GoF 원서가 아니라 논문이므로 장·절 이름이 곧 위치다.
- 비교 절에 **Strategy** 를 반드시 넣는다 — 술어 객체를 갈아 끼우는 모양이 Strategy 와 같아 보인다. 카드 `.4` 의 교훈 15~17번을 적용해, 두 패턴의 `[필수]` 를 동시에 만족하는 코드가 서는지 **조건을 세울 때** 확인한다.
- 기존 33편에서 이 패턴을 정의 없이 가리키는 자리가 있으면 상호 링크를 건다.

### WP2 · `S2` Temporal Property — `analysis-guide` 트랙

원전은 eaaDev(Fowler 의 저자 공개 보충 자료). 다루는 것은 코드 구조가 아니라 **시간에 따라 값이 달라지는 속성의 모델링**이다.

**완료 기준**: WP1 과 같은 다섯 + 분석 트랙 요구 둘 — 상황 설정 표 네 행이 모두 채워질 것(AG3 의 빈칸 표현 금지), `ddd-tactical-terms` 참고 문서 링크(AG4).

**이 편에만 있는 요구 셋**
- **Range 편과의 경계를 먼저 긋는다.** 분석 README 가 「Range 를 유효 기간으로 쓴다」고 적은 편이 셋인데 유효 기간 모델링 자체는 어느 편도 정의하지 않는다 — 그 빈자리를 메우는 것이 이 편의 존재 이유다. Range 편은 **구간이라는 값**을, 이 편은 **그 구간에 매인 속성**을 다룬다.
- 비교 절에 **Range · Observation · Knowledge Level** 을 넣는다. 셋 다 시간 축을 쓰는 편이다.
- Effectivity · Dual Time Record 를 이 편 안의 갈래로 흡수한다(후보 보고서의 배정). 단독 편으로 쪼개지 않는다.

## 2. 의존과 순서
<!-- 이 배치 안에서 무엇이 무엇을 기다리는가. 배치 밖 의존이 있으면 여기 적는다. -->
두 work 는 트랙이 달라 파일도 spec 도 겹치지 않는다(`design-pattern-guide/specification/` vs `ddd-analysis-pattern-guide/temporal-property/`). **배치 안 의존 없음** — 병렬로 돌릴 수 있다.

**배치 밖 의존은 해소됐다.** `S3`·`S4` 가 기다리던 PG27 열거 확장은 2026-09-30 에 끝났고(`BASIS_SOURCES` 에 `Woolf`·`PLoP`), 이 배치의 둘은 원래 걸리지 않았다 — Specification 은 `Evans`·`apsupp`, Temporal Property 는 `eaaDev` 가 이미 목록에 있다.

**순서**: 병렬 위임하되 `S1` 을 먼저 낸다. Specification 의 비교 절이 Strategy 를 다루므로, 거기서 나오는 동시 통과 판정 방식이 `S2` 의 비교 절(Range·Observation·Knowledge Level 셋)에 그대로 쓰인다.

**파일 소유권**: 워커는 자기 편의 폴더 하나만 쓴다. 인덱스(`PATTERNS.md`)·검증 숫자·`gate-results.jsonl` 은 **메인이 배치 끝에 한 번에** 고친다 — 두 워커가 같은 줄을 건드리면 충돌한다.

## 3. 리스크
<!-- 이 배치가 예산을 넘길 지점, 되돌리기 어려운 지점. -->
- **가장 큰 위험은 Specification ↔ Strategy 동시 통과다.** 2026-09-30 실측에서 여덟 쌍이 모두 동시 통과했고 그중 일곱이 양방향이었다. 술어 객체는 Strategy 의 `[필수]` 를 그대로 만족할 소지가 크다 — 조건을 세울 때 **발행된 Strategy 편을 판정해 보고**, 갈리지 않으면 비교 절에서 가르는 문장을 먼저 쓴 뒤 조건을 맞춘다.
- **원전이 논문·웹 문서라 인용 위치가 흔들린다.** GoF 원서처럼 장·절 번호가 고정돼 있지 않다. 근거 괄호에 **문서 제목 + 절 이름**을 함께 적고, 조회일을 참고 자료에 남긴다.
- **분석 트랙의 상황 설정 표가 배경 확정안에 걸릴 수 있다.** Temporal Property 가 회계 예를 들면 확정안(`accounting-context.md`)의 불변식과 어긋날 여지가 있다 — 회계가 아닌 도메인으로 예를 잡으면 이 위험이 사라진다.
- **세션 한도.** 앞선 배치들에서 워커가 429 로 끊긴 적이 네 번 있었다. 끊기면 `SendMessage` 로 같은 워커를 이어받아 완주시킨다(새로 띄우지 않는다 — 앞 라운드 사본이 사라진다).

## 4. 착수 시점 판단
