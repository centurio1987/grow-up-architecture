### 두 편의 모양이 서로 다르다

**Memento 는 State 형이다 — 한 편이 깊게 가리킨다.** Command 편 혼자 10회이고 그중 여섯이 실질이다. `:278`(비교 표)·`:309`(산문)이 구분 기준을 고정했다 — 「나중에 쓰려고 건네는 토큰이 **다형적 실행 연산**을 갖는가, **값으로만 전달되는 좁은 인터페이스**인가」(근거: GoF 5장 행위 패턴 토론). `:315` 세 줄 도식, `:319` 포개짐(근거: GoF Command 절 Related Patterns), `:331` 오차 누적, `:184`·`:210` 사용 단서. **Strategy ↔ State 때처럼 상대 편이 이미 축을 세워 뒀으므로 뒤집어 받으면 된다.**

**Iterator 는 지금까지 없던 모양이다 — 가리킨 넷 중 셋이 「차이」가 아니다.**

- **Composite 5** (`:290`·`:352`) — 유일한 진짜 구분 기준: 「**순회 순서를 누가 쥐는가** — 노드 자신인가 밖의 순회자인가」. Composite 는 노드가 쥐고 Iterator 는 트리 밖 순회자로 뺀다
- **Factory Method 9** — **차이가 아니라 포개짐 주장이다.** 그 편이 `Iterable.iterator()`·`IntoIterator::into_iter()` 를 **팩토리 메서드로 판정**했고(`:936`·`:938` 표, `:940` 최소 조건 대조, `:948`·`:951` 결합 시점), 근거로 **원전 Iterator 절이 순회자를 만드는 연산을 팩토리 메서드의 예로 든다**는 서술을 달았다(`:1041`, 5장 257쪽). **Iterator 편이 이것을 부정하면 두 편이 충돌한다** — 반대 방향에서 받아야 한다
- **Adapter 1**(`:973`) · **Decorator 1**(`:922`) — **이름 혼동 경고다.** Rust `Read::bytes()` 는 Adapter 쪽, 표준 라이브러리가 "iterator adapters" 라 부르는 `map`·`filter`·`take` 는 Decorator 쪽이라고 각 편이 이미 못 박았다. **Iterator 편이 같은 API 를 자기 사례로 끌어오면 그 자리가 어긋난다**

즉 Iterator 의 위험은 **구분 기준 누락이 아니라 영역 침범**이다. 워커 입력에 네 편의 자리를 행 번호까지 주고 「부정하지 말고 받으라」를 명시한다.

### 배치9 가 확인해 준 것 — 규칙 둘을 그대로 간다

배치8 이 세운 둘이 배치9 에서 **각각 1라운드에 걸렸다.** 유지한다.

1. **`[필수]` 근거를 조각 단위로 덮기** — CoR 1R PG27 이 이것으로 났다(조건 1의 한 조각이 Motivation·Structure 에서 온 것을 잡아 `[선택]` 으로 내림)
2. **조건 경로 ↔ 비교 절 경로 교차 판정 표** — Template Method 1R E1 이 이것으로 났다(A≠B 2건). 닫은 방법이 재사용 가능하다 — **판정 단위를 좁히는 것**(상위 타입 하나 → 상위·하위 타입의 짝)이고, 근거는 **원전 문장의 주어**였다

**Iterator 에서 이 둘이 걸릴 자리를 미리 짚는다.** 교차 판정 표의 시험 사례에 **Factory Method 편이 팩토리 메서드로 판정한 `Iterable`·`IntoIterator` 행을 반드시 넣는다** — 경로 A(Iterator 최소 조건)와 경로 B(비교 절)가 그 둘에 같은 답을 내야 하고, 그 답은 **「둘 다이다」** 여야 앞 편과 맞는다.
