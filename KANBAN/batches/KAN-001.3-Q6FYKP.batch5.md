## 1. 작업 패키지

### WP1 · `S9` Strategy v1.1.0 — 새 골격의 첫 실물

세 편 중 가장 짧아 먼저 쓴다. 완성되면 **유저에게 새 모양을 보이고** 그 반응을 S10·S11 에 반영한다.

- 시나리오 후보: ① 기본 흐름 — 주문 하나의 배송비가 정액 요금제로 계산되는 길 ② 변화가 들어올 때 — "50,000원 이상 무료" 요금제가 추가될 때 무엇이 바뀌고(새 클래스 하나, 조립 코드 한 줄) 무엇은 안 바뀌는가(Checkout) ③ 경계를 넘을 때 — Checkout 안에서 요금제를 `switch` 로 고르면 ②의 변화가 어느 단계에서 Checkout 수정으로 번지는가.
- 원서 의존 28줄의 처분: 구현 쟁점 1·2·3(데이터 전달 세 방식 · 템플릿 매개변수 · 기본 전략)은 **주제 안이라 본문에서 푼다**. Flyweight 내재 상태 · Command 의 Invoker/Receiver 는 `gof-vocabulary` 참고 문서로 링크. "원서는 … 꼽아요" 류는 근거 괄호로 내리고 이유를 본문에 쓴다.
- 코드는 v1.0.0 의 `code/` 를 그대로 쓰되 시나리오 ②③ 이 코드에 없으면 진입점을 보강한다(250줄 상한 안에서).

**완료 기준**: `resolve --frozen` 통과 → `check-guides --all --compile --run` 통과 → 품질 게이트 PASS(3라운드 이내) → HTML 렌더 → `gate-results.jsonl` 1줄 → 인덱스·`exemplars`·analyzer 가 v1.1.0 을 가리킴(`--pointers` 통과) → v1.0.0 `status: legacy`.
