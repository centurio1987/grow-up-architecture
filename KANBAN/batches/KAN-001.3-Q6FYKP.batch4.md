# KAN-001.3-Q6FYKP 배치4 — 명세 1.4.0 과 참고 문서 4편

카드: [KAN-001.3-Q6FYKP.md](../cards/KAN-001.3-Q6FYKP.md) · 범위 `S7` · `S8`
선행: [배치3](KAN-001.3-Q6FYKP.batch3.md)

> **이 문서는 착수 전 계획이다.** 수행 내역은 카드 실행 문서의 「수행 내역」에 있다.

유저가 파일럿 세 편을 읽고 낸 지적 두 건(검토서 항목 18·19, 2026-09-21)이 이 배치의 입력이다.

- "원서는 외부 레퍼런스이고, 링크로만 존재한다. 가이드의 컨텐츠가 아니다. … 사전 이해가 필요하다면, 별도의 가이드나 참고 문서를 작성해서 내부 참조를 하도록 만들어라."
- "정적인 설명만 가득하다. 시나리오에 따른 절차와 절차별 설명이 없다. 스펙 보다는, 이해를 위한 개념적 레벨에서의 설명이 가이드의 주요 컨텐츠다."

둘 다 개별 문장이 아니라 **명세가 만든 모양**이다 — GG1·GG2 가 "원전 participants 를 센다 / collaborations 를 옮긴다"라서 가이드가 원서 요약이 됐고, 시나리오 절이 편당 하나(전체의 3~4%)였다. 그래서 문장을 고치지 않고 명세를 고친다.

## 1. 작업 패키지

### WP1 · `S7` 명세 1.4.0 — 자립성 원칙과 시나리오 골격

두 트랙 spec 을 1.4.0 으로 올리고, 참고 문서 종류 `reference-note` 를 신설하며, 검사기가 새 규칙을 기계로 잡게 한다.

- 원칙: PG30 자립성(원서 위치 지시자는 근거 괄호·참고 자료에만) · PG31 권위 인용은 설명이 아니다 · PG32 시나리오 2개 이상, 단계마다 왜 · PG33 조건·비교가 시나리오를 가리킨다 · PG34 구현 해설은 줄 포인팅 · PG35 한 도메인. GG1·GG2 는 리서치 노트 대조로, AG4 잠정 규칙은 참고 문서 링크로.
- 골격: `### 동작 절차`·`### 등장하는 개념과 정의` → `### 시나리오 n — 제목`(반복) + `### 개념 정리`.
- 참고 문서 spec: `pattern-guide/reference/<slug>/<slug>-ref_v<semver>.md`, 절 6개, 원칙 RN1~RN7.
- 검사기: `self-contained`(PG30) · `scenarios`(PG32) · `scenario-ref`(PG33) · 참고 문서 파일명·frontmatter·`serves`·포인터·게이트 기록.

**완료 기준**: `validate --all` 통과 · 공유 블록 바이트 동일 · `lock --update` 커밋 · 자가 테스트 전부 통과 · 옛 골격의 v1.0.0 세 편이 새 검사에서 떨어지는 것을 확인(새 검사가 실제 문장을 잡는지).

### WP2 · `S8` 참고 문서 4편

가이드가 기대는 주제 밖 사전 지식을 원서 없이 읽히게 푼다. 패턴 판정·비교·구현은 싣지 않는다(RN7).

| slug | 답하는 것 | 링크할 가이드 |
| --- | --- | --- |
| `gof-vocabulary` | GoF 원서가 여러 패턴에 걸쳐 쓰는 어휘 — 내재/외재 상태, Invoker/Receiver, 정적/동적 디스패치, 클래스 패턴/객체 패턴, 컴파일 시점/실행 시점 결합 | GoF 23편 |
| `ddd-tactical-terms` | Bounded Context · Aggregate · Root · Entity · Value Object · id 참조 · 불변식 | 분석 10편 |
| `accounting-model` | Fowler 6장의 Account/Entry/Transaction/Posting Rule/Money 개념 지도 + 복식부기 기초(차변/대변 부호 규약 · 원장 · 전기 · 역분개 · knowledge level) | Account · Transaction · Posting Rule |
| `observation-model` | Fowler 3장의 Quantity/Unit/ConversionRatio/CompoundUnit/Measurement/Observation/Range 개념 지도 | Quantity · Range · Measurement · Observation |

**완료 기준**: 편마다 기계 검사 통과 + 품질 게이트 PASS(3라운드 이내) + HTML 렌더 + `gate-results.jsonl` 1줄.

## 2. 의존과 순서

- `S7` → `S8`. 참고 문서는 `reference-note` spec 과 캔버스가 있어야 쓴다.
- `S7` 안에서 명세(`.claude/**`)와 검사기(`scripts/**`)는 파일이 갈리므로 병렬. 검사기는 spec.json 의 sections 를 읽어 동작하니 새 골격은 픽스처 spec 으로 먼저 검증한다.
- `S8` 네 편은 파일이 전부 다르므로 폭 4 병렬. 입력은 `pattern-guide/research/` 노트(gof-*.md · analysis-patterns.md · accounting-context.md).
- 배치 밖: `S9`~`S11`(세 편 v1.1.0)이 이 배치의 참고 문서에 내부 링크를 건다. 참고 문서의 slug·경로를 여기서 확정한다.

## 3. 리스크

- **명세 개정 뒤 v1.0.0 세 편이 전부 검사에서 떨어진 상태가 된다.** 예정된 상태다 — v1.1.0 이 나올 때까지 `--all`·`--gates` 는 실패를 낸다. 발행 상태(`published`)는 v1.1.0 이 게이트를 통과한 뒤 바꾼다.
- 시나리오 골격을 세 편에 얹으면 분량이 늘 수 있다. 상한은 두지 않되, 구현 절 해설이 시나리오 단계 포인팅(PG34)으로 줄어드는 만큼 상쇄되는지 S9 에서 실측한다.
- 참고 문서가 원서 요약이 되면 지적 1 을 자리만 옮긴 것이 된다. RN1(자립)·RN2(개념마다 예)가 그것을 막고, 채점이 "원서 없이 읽히는가"를 본다.
