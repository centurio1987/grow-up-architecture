# KAN-001.7-4MRJ1B 배치2 — Dependency Injection 과 Null Object (둘 다 GoF 트랙)

카드: [KAN-001.7-4MRJ1B.md](../cards/KAN-001.7-4MRJ1B.md) · 범위 `S3` · `S4`
선행: 배치1(`S1` Specification · `S2` Temporal Property) — **발행 완료**

## 0. 착수 전에 확인한 사실 — 두 편의 채택 근거가 바뀌었다

리서치 노트가 든 첫 근거가 **33편 재집필 과정에서 소멸했다**(2026-09-30 메인 실측). 워커에게 낡은 근거를 넘기면 본문이 틀린 말을 하게 되므로 여기 적어 둔다.

- **DI** — 노트는 「GoF 6편이 DI 를 정의 없이 언급한다」고 적고 줄 번호 열 곳을 댔다. 현행 발행본에서 `의존성 주입`·`Dependency Injection` 은 **singleton 편 3회뿐**이고 나머지 다섯(strategy · factory-method · abstract-factory · flyweight · mediator)은 **0회**다. 노트의 줄 번호는 전부 폐지된 `*-pattern.md` 기준이다. 남은 셋도 「정의 없이」가 아니다 — `singleton:174` 가 괄호 안에서 짧게 푼다.
- **Null Object** — 노트는 `strategy-pattern.md:84` 가 `NoDiscountStrategy` 를 「Null Object 형태」라 부른다고 적었다. 현행 발행본 전체에서 `Null Object`·`널 객체` 는 **0회**이고, 그 자리는 Strategy 편이 도메인을 배송 요금으로 바꿔 쓰면서 없어졌다.

**그래도 채택은 유효하다.** 유저가 2026-09-30 에 넷 전부 채택으로 결정했고(2026-09-27 승인의 재확인), 두 편의 가치는 다른 근거가 진다.

- DI: `singleton` 편이 비교 절에서 **「의존성 주입 컨테이너의 단일 스코프」를 갈래로 다루는데**(`:245`·`:270`) 그 갈래를 풀 자리가 괄호 한 줄뿐이다. Fowler 원전의 Service Locator 논쟁과 세 형태도 그대로다.
- Null Object: Rust 에 null 참조가 없어 **「언어가 부재를 타입으로 강제할 때도 이 패턴이 필요한가」**가 세 언어 대조에서 드러난다. 원전 쪽의 「오류를 정상 실행처럼 보이게 한다」 비판도 안티패턴 갈래 소재로 남아 있다.

노트는 정정해 두었다(`research/candidates.md` 의 두 절 머리에 ★ 정정 블록).

## 1. 작업 패키지
<!-- work 하나에 WP 하나. 각 WP 는 완료 기준으로 끝난다. -->
### WP1 · `S3` Dependency Injection — `gof-guide` 트랙

원전은 Fowler 「Inversion of Control Containers and the Dependency Injection pattern」(2004-01-23, bliki 밖의 articles 쪽). 세 형태는 Constructor · Setter · Interface Injection 이다.

**완료 기준**: `resolve --frozen` 통과 · 독립 채점 PASS(라운드 ≤ 3, 자기 채점 금지) · `check-guides --all --compile --run` 0 · `gate-results.jsonl` 1줄 · HTML 렌더 + 도식 검사 통과.

**이 편에만 있는 요구 넷**
- **Strategy 와 갈리지 않는다.** Strategy 의 `[필수]` 3번이 「고르는 분기가 Context 안에 없고 받는 경로가 있다」인데 그것이 곧 주입이다. 배치1 의 Specification 편이 세운 방식을 그대로 쓴다 — **막지 말고 밝힌다.** 가르는 것은 의도이고(교체 가능한 알고리즘 vs 구성과 사용의 분리), 코드에서는 **주입되는 것이 알고리즘 하나인가 협력 객체 일반인가**를 본다.
- **Service Locator 를 비교 절의 갈래로 흡수한다.** 단독 편으로 쪼개지 않는다(후보 보고서의 배정). Fowler 의 결론 문장(「둘 사이의 선택보다 **구성과 사용을 분리한다는 원칙**이 더 중요하다」)을 그 갈래의 맺음으로 쓴다.
- **`singleton` 편과 상호 링크한다.** 그 편이 이미 「의존성 주입 컨테이너의 단일 스코프와의 차이」 갈래를 갖고 있으므로(`:270`), 이 편이 서면 그 갈래가 가리킬 자리가 생긴다. 스킬 4단계의 상호 참조 규약을 따른다 — **`singleton` 쪽 링크 추가는 메인이 제자리로** 한다.
- 컨테이너 없이 순수 생성자 주입으로 쓴다. Rust 는 제네릭 매개변수나 `Box<dyn Trait>` 를 쓰되 **연산이 `&self` 면 `Rc<dyn Trait>` 로 충분하다**(`.4` 카드에 실측으로 박힌 정정).

### WP2 · `S4` Null Object — `gof-guide` 트랙

원전은 Woolf 「Null Object」(PLoPD3 「General Purpose Design Patterns」 부의 1장). 선행 발표는 Kühne 「Void Value」(1996), 일반화는 PoEAA Special Case(18장)다.

**완료 기준**: WP1 과 같은 다섯.

**이 편에만 있는 요구 넷**
- **Strategy 와 구조가 같다.** 「아무것도 하지 않는 구체 전략」이 곧 이 패턴의 모양이다. WP1 과 같이 막지 말고 밝히되, 가르는 것은 **그 구현이 대안 하나인가 부재의 표현인가**다.
- **Rust 가 이 편의 핵심 대비다.** Rust 에는 null 참조가 없고 `Option` 이 부재를 타입으로 강제한다. 세 언어 구현 절에서 **「언어가 부재를 타입으로 막아 줄 때도 이 패턴이 필요한가」**에 코드로 답한다 — 그것이 이 편이 세 언어를 쓰는 이유다.
- **안티패턴 갈래를 반드시 둔다.** 원전 쪽 비판이 「오류를 정상 실행처럼 보이게 만든다」다. 중립 동작이 **삼켜야 하는 것과 삼키면 안 되는 것**을 가르는 기준을 코드로 보인다.
- PoEAA Special Case 와의 관계는 **일반화-특수화**로 적는다. 경쟁이 아니다.

## 2. 의존과 순서
<!-- 이 배치 안에서 무엇이 무엇을 기다리는가. 배치 밖 의존이 있으면 여기 적는다. -->
두 work 는 폴더가 다르다(`design-pattern-guide/dependency-injection/` vs `null-object/`). **배치 안 의존 없음** — 병렬로 돌린다.

**같은 spec 을 쓰므로 배치1 이 세운 방식을 둘이 함께 물려받는다.** GoF 원서 밖 원전의 근거 괄호를 **문서 제목 + 절 이름**으로 적는 방식이 Specification 편에서 정해졌다. `BASIS_SOURCES` 는 DI 의 Fowler articles 를 `Fowler`·`martinfowler` 로, Null Object 의 Woolf PLoP 논문을 `Woolf`·`PLoP` 으로 받는다 — **둘 다 이미 목록에 있어 선행 작업이 없다.**

**파일 소유권**: 워커는 자기 편 폴더 하나만 쓴다. 인덱스(`PATTERNS.md` 의 「GoF 밖 설계 패턴」 범주)·`singleton` 편 상호 링크·검증 숫자·`gate-results.jsonl` 은 **메인이 배치 끝에 한 번에** 고친다.

## 3. 리스크
<!-- 이 배치가 예산을 넘길 지점, 되돌리기 어려운 지점. -->
- **둘 다 Strategy 와 동시 통과할 것이 거의 확실하다.** 배치1 의 Specification 이 이미 그랬고, 이 둘은 리서치 노트가 먼저 「Strategy 와 겹친다」고 적었다. 조건을 좁혀 막으려 하면 Strategy 의 정당한 변형이 탈락한다 — **조건을 세울 때 발행된 Strategy 편을 판정해 보고, 갈리지 않으면 비교 절의 가르는 문장을 먼저 쓴 뒤 조건을 맞춘다.**
- **DI 는 「패턴인가 원칙인가」가 흔들리기 쉽다.** 원전이 스스로 Inversion of Control 이라는 이름이 너무 일반적이라고 적는다. 최소 조건을 **코드에서 관찰 가능한 구조**로 적지 못하면 `gof-guide` 트랙이 성립하지 않는다 — 착수 때 이것부터 정한다.
- **Null Object 는 `[필수]` 가 너무 적어질 수 있다.** 「같은 인터페이스 + 중립 동작」 둘로 끝나면 Strategy 의 부분집합이 된다. 부재의 표현이라는 의도를 **관찰 가능한 형태**로 옮길 조건이 하나는 있어야 한다.
- **산문 연속 상한은 이제 기계가 잡는다**(2026-09-30 `check_prose_run` 추가). 배치1 에서 이 MUST 가 채점자 손에만 있어 한 편이 6 으로 올라왔고 발행본 하나(`party`)는 5 로 새어 나가 있었다. 이제 `--all` 이 실패로 잡으므로 워커가 스스로 본다.
- **세션 한도.** 앞선 배치에서 429 가 네 번 있었다. 끊기면 `SendMessage` 로 같은 워커를 이어받아 완주시킨다(새로 띄우지 않는다 — 앞 라운드 사본이 사라진다).
