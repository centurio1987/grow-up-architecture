## P15 농산물 꾸러미 정기 배송 — 콘셉트 문서 + 농부 메모 + 주문 엑셀

| 난이도 | 씨앗 형식 | 중심 산출물 | 연결 장 |
| --- | --- | --- | --- |
| 상 | 콘셉트 문서(형식 있음) + 농부 메모·주문 엑셀(거친 자료) | 네 층 전부와 검증 | 전체 |

### 상황

「들녘꾸러미」는 이웃 농가 다섯 곳의 농산물을 꾸러미로 묶어 매주 목요일에 보내는 작은 정기 배송입니다. 지금까지 운영자 한 명이 엑셀 한 장으로 구독자와 결제를 관리했는데, 구독자가 서른 명을 넘으면서 결제가 자주 틀린다는 이야기가 나왔어요. 운영자가 처음 서비스를 열 때 쓴 콘셉트 문서, 농부 두 분이 보낸 메모, 그리고 11월 결제까지 적힌 주문 엑셀을 받았습니다. 이 세 자료로 네 산출물을 설계하고, 설계한 규칙으로 11월 결제를 다시 계산해 엑셀과 견줘 주세요.

### 주어진 자료

**자료 1. 콘셉트 문서** (운영자, 2026년 9월)

```text

2 구독자는 꾸러미 크기(소·중·대)와 받는 주기(매주·격주)를 고릅니다.
  격주는 홀수 주나 짝수 주 가운데 하나로 받습니다.
3 꾸러미 가격은 소 18,000원, 중 25,000원, 대 32,000원입니다.
  매달 말일에 그달 받은 꾸러미 수만큼 결제합니다.
4 받고 싶지 않은 주는 배송 전 주 일요일 자정까지 앱에서 건너뛸 수 있습니다.
  건너뛴 주는 결제하지 않습니다.
5 꾸러미 구성은 그 주 수확에 맞춰 농부들이 정하고, 수요일 오후 6시에 확정합니다.
6 알레르기가 있는 품목을 알려 주시면 다른 품목으로 바꿔 드립니다.
```

### 과제

1. **원장.** 세 자료에서 원장 줄을 뽑으세요. 근거 수준을 자료마다 다르게 붙이고, 그 이유를 적으세요(7장, 21장).
2. **엑셀 맞추기.** 엑셀의 표기 흔들림(크기·주기·시작일), 겹치는 연락처, 배송 지역 밖, 비고 칸을 정리하고, 맞추기 결정과 미결 질문을 적으세요.
3. **개념 스키마.** 2장 표기로 쓰세요. 콘셉트 문서의 모호한 문장마다 어떤 가정을 두었는지 적으세요.
4. **외부 스키마.** 구독자의 "내 구독"(V1)과 농부의 "회차 필요량"(V2)을 다섯 항목으로 쓰세요. V2는 11월 26일 회차의 토마토·달걀·두부 필요량을 실제로 계산해 보이세요.
5. **계약.** 건너뛰기 연산 O1의 행위 겹과 실패표, 결제 대행사로 넘기는 월 결제 파일 E1의 구조·의미·품질 겹을 쓰세요.
6. **내부 스키마.** 표와 제약을 쓰고 보장 위치표를 채우세요.
7. **검증.** 설계한 규칙으로 11월 결제를 다시 계산해 엑셀과 다른 행을 원인별로 나누세요. 내부 스키마로 인구 왕복을 하고, 규칙마다 반례 시험을 하세요(13장).

### 풀이

계산한 숫자는 모두 `verification/check_p15.py`의 출력(`verification/p15-result.json`)에서 옮겼습니다. 실행 환경은 Python 3의 sqlite3 모듈(SQLite 3.53.0)입니다.

#### 1. 원장

자료마다 근거 수준이 다릅니다. 콘셉트 문서는 운영자가 "이렇게 한다"고 말한 것이라 **진술**이고, 농부 메모도 진술이지만 "정도", "듯", "반쯤?" 같은 말이 붙은 줄은 불확실한 진술로 표시합니다. 엑셀은 실제로 일어난 일을 적은 것이라 **관찰**이에요. 엑셀에서 보인 규칙성은 규칙이 아니라 관찰된 패턴일 뿐입니다.

#### 2. 엑셀 맞추기

스크립트로 센 값부터 보겠습니다.

```text
행 수                30
크기 원본 값          소 12 · 중 8 · 대 7 · M 1 · 중간 1 · L 1
주기 원본 값          매주 21 · 격주 7 · 격주(짝) 1 · 2주 1
시작일 꼴             YYYY-MM-DD 26 · YYYY.MM.DD 1 · M/D(연도 없음) 2 · 비어 있음 1
연락처가 겹치는 행     010-1000-0010 → 10번, 11번
배송 지역 밖          9번(북구)
11월 목요일(ISO 주차)  11-05(45) · 11-12(46) · 11-19(47) · 11-26(48)
```

| 흔들림 | 결정 | 근거 |
| --- | --- | --- |
| 크기 M·중간 / L | 중 / 대로 맞춤 | 값이 셋뿐인 열에서 다른 표기가 한 번씩. 운영자 확인 필요(진술로 올림) |
| 주기 2주·격주(짝) | 격주로 맞추고, (짝)은 배송 주차로 | 1-2: 격주는 홀·짝 가운데 하나 |
| 시작일 세 꼴 | 날짜로 맞춤. 연도 없는 10/15·10/1은 2026년으로 | 다른 행이 모두 2026년 |
| 시작일 없음(27번) | 계산하지 않고 q로 | 기록 결제 72,000원은 네 회를 받았다는 뜻으로 보이지만 추정일 뿐 |
| 10·11번 같은 연락처 | 같은 구독자. 11번은 새 구독이 아니라 11-15부터의 **주소 변경** | 비고 "이사함", 크기·주기 같음 |
| 9번 북구 | 배송 지역 밖. 설계에는 넣지 않고 q3 | 1-7과 어긋남 |
| 비고 칸 | 다섯 갈래로 나눔: 알레르기(10·16·29번), 지역 밖 요금(9번), 이사(11번), 해지(20번), 결제자(23번), 배송 실패(30번) | 한 칸에 서로 다른 사실이 섞여 있음 |

비고 칸이 23장에서 말하는 "여러 사실을 담은 칸"의 전형입니다. 알레르기는 구독자에 딸리고, 결제자는 구독에 딸리며, 배송 실패는 회차에 딸린 사실이에요. 칸 하나를 다섯 갈래의 사실 유형으로 나눠야 합니다.

#### 3. 개념 스키마

```text
[개체] 구독자(구독자 번호)              이름 · 연락처(유일 — q6 답 전까지 진술 없음)
[개체] 구독(구독 번호)
[개체] 꾸러미 크기(크기 이름)           가격                         {소, 중, 대}
[개체] 배송 회차(배송일)                ISO 주차                      배송일은 목요일
[개체] 품목(품목 코드)                  이름 · 표시 문구(선택, 예: 방사란)
[개체] 농부(농부 번호)                  이름

[사실] F1  구독자 는 [시작일, 종료일) 동안 주소 에 산다 (구 포함)       ← 10·11번
[사실] F2  구독 은 구독자 가 받고 결제자 가 낸다                       ← 23번
[사실] F3  구독 은 크기 · 주기{매주, 격주} · 배송 주차{홀, 짝} · 시작일 · 종료일 을 가진다
[사실] F4  구독 은 배송 회차 를 건너뛰었다 (요청 시각)
[사실] F5  구독 은 배송 회차 에 배송이 실패했다 (사유)                  ← 30번
[사실] F6  배송 회차 에 크기 꾸러미는 품목 을 양 만큼 담는다 (확정 시각)
[사실] F7  농부 는 배송 회차 에 품목 을 양 만큼 낼 수 있다
[사실] F8  구독자 는 품목 에 알레르기가 있다
[사실] F9  품목 은 알레르기 대체 품목 과 양 을 가진다                   ← m6 달걀 → 두부 한 모
[사실] F10 품목 은 농부 가 낸다

[제약] R1  배송 주차는 격주 구독만 가진다
[제약] R2  건너뛰기 요청 시각 < 마감 (가정 a3)
[제약] R3  주소의 구는 {동구, 서구, 남구}                               ← q3 답에 따라 바뀜
[제약] R4  한 구독자의 구독 기간은 겹치지 않는다 (가정 — q6)
[제약] R5  꾸러미 구성(F6)은 확정 시각(수요일 18:00) 이후 바뀌지 않는다
[제약] R6  종료일 > 시작일

[파생] D1  예정 회차 = 시작일 이후, 종료일 전의 배송 회차 가운데
            매주이거나, 격주이고 ISO 주차의 홀짝이 배송 주차와 같은 것
[파생] D2  받은 회차 = 예정 회차 - 건너뛴 회차(F4) - 배송 실패 회차(F5)
[파생] D3  결제자의 월 결제액 = 그달 받은 회차 수 × 크기 가격
[파생] D4  회차 필요량(품목) = 크기별 받을 꾸러미 수 × 크기별 담는 양, 알레르기 대체 반영

[가정] a1  홀·짝 주는 ISO 주차(월요일 시작)                               q2
[가정] a2  배송 주차를 정하지 않은 격주 구독은 시작일 뒤 첫 목요일의 주차를 따름  q2
[가정] a3  마감은 배송일 직전 일요일 24:00 (= 월요일 00:00, 배송일 3일 전 0시)   q1
```

a3에 대해 덧붙이겠습니다. "배송 전 주 일요일"을 한 주가 일요일에 시작한다고 읽으면, 11월 12일(목) 배송의 "전 주 일요일"은 11월 1일이 됩니다. 마감이 11일 전이에요. 월요일 시작으로 읽으면 직전 일요일인 11월 8일이고 4일 전입니다. 마감이 일주일이나 달라지는 모호함이라, 가정을 두고 설계를 진행하되 q1의 답을 가장 먼저 받아야 합니다.

```text
  고르기   배송일 = 다음 목요일, 품목은 그 농부가 내는 것(F10)
  가림     구독자 이름·주소는 보이지 않음 (필요량만)
  시점     구성 확정(수요일 18:00) 전에는 "예상", 뒤에는 "확정"으로 표시
  갱신     읽기 전용. 낼 수 있는 양은 농부의 명령으로 따로
```

V2를 11월 26일 회차로 계산하면 이렇습니다. 그 회차에 받을 꾸러미는 소 5개, 중 8개, 대 7개예요. 건너뛰기가 있는 13번(11/19, 11/26)과 22번(11/26)은 빠졌고, 격주 가운데 짝수 주(48주)인 5·12·17·28번만 들어갔습니다. 소 5개 가운데 2개(10번, 29번)는 달걀 알레르기라 두부로 바꿉니다.

```text
토마토  5 × 300g + 8 × 600g + 7 × 1,000g = 1,500 + 4,800 + 7,000 = 13,300g
달걀   (5 - 2) × 6구 + 8 × 10구 + 7 × 15구 = 18 + 80 + 105 = 203구 → 30구 한 판 단위로 7판(210구)
두부   2모
```

토마토 양(m2)은 "정도", "듯"이 붙은 불확실한 진술이라 V2의 모든 값이 "예상"입니다. 김농부가 다음 주 수확을 "반쯤?"(m1, 약 20kg)이라 했으니 13.3kg은 낼 수 있는 양 안에 들어올 것으로 보이지만, 이것도 진술에 기댄 추정이에요.

#### 6. 내부 스키마

검증에 쓴 SQLite 판 DDL의 요점입니다. 전체는 `verification/check_p15.py`에 있어요.

```sql
PRAGMA foreign_keys = ON;   -- SQLite 는 외래 키 검사가 기본으로 꺼져 있음

CREATE TABLE box_size (size TEXT PRIMARY KEY, price_won INTEGER NOT NULL CHECK (price_won > 0));
CREATE TABLE subscriber (subscriber_id TEXT PRIMARY KEY, name TEXT NOT NULL, phone TEXT NOT NULL UNIQUE);
CREATE TABLE subscriber_address (
  subscriber_id TEXT NOT NULL REFERENCES subscriber(subscriber_id),
  valid_from TEXT NOT NULL, valid_to TEXT, address TEXT NOT NULL,
  district TEXT NOT NULL CHECK (district IN ('동구','서구','남구')),        -- R3
  PRIMARY KEY (subscriber_id, valid_from));
CREATE TABLE subscription (
  subscription_id TEXT PRIMARY KEY,
  subscriber_id TEXT NOT NULL REFERENCES subscriber(subscriber_id),
  payer_id      TEXT NOT NULL REFERENCES subscriber(subscriber_id),        -- F2
  size   TEXT NOT NULL REFERENCES box_size(size),
  period TEXT NOT NULL CHECK (period IN ('매주','격주')),
  parity TEXT CHECK (parity IN ('홀','짝')),
  start_date TEXT NOT NULL, end_date TEXT,
  CHECK ((period = '격주') = (parity IS NOT NULL)),                         -- R1
  CHECK (end_date IS NULL OR end_date > start_date));                       -- R6
-- R4: 한 구독자의 구독 기간 겹침을 막는 BEFORE INSERT 트리거
CREATE TABLE delivery_day (delivery_date TEXT PRIMARY KEY CHECK (strftime('%w', delivery_date) = '4'),
                           iso_week INTEGER NOT NULL);
CREATE TABLE skip (
  subscription_id TEXT NOT NULL REFERENCES subscription(subscription_id),
  delivery_date   TEXT NOT NULL REFERENCES delivery_day(delivery_date),    -- pre2 의 일부
  requested_at    TEXT NOT NULL,
  PRIMARY KEY (subscription_id, delivery_date),                            -- post2 멱등
  CHECK (julianday(requested_at) < julianday(delivery_date, '-3 days')));  -- R2 (a3)
CREATE TABLE delivery_failure (
  subscription_id TEXT NOT NULL REFERENCES subscription(subscription_id),
  delivery_date   TEXT NOT NULL REFERENCES delivery_day(delivery_date),
  reason TEXT NOT NULL, PRIMARY KEY (subscription_id, delivery_date));     -- F5
```

| 항목 | 지키는 자리 | 방법 |
| --- | --- | --- |
| R1 격주만 주차 | DB | `CHECK` |
| R2 건너뛰기 마감 | DB + O1 | `CHECK`(julianday 비교) + O1 pre3 검사로 409 |
| R3 배송 지역 | DB | `CHECK` (q3 답이 오면 바뀜) |
| R4 구독 기간 겹침 | DB | 트리거 |
| R5 구성 확정 뒤 불변 | 응용 | 확정 시각 이후 F6 수정 명령을 거부. 주 1회 감시 질의 |
| 배송일은 목요일 | DB | `delivery_day`의 `CHECK`와 외래 키 |
| D1~D3 결제 | 질의 | 결제 질의(스크립트의 `BILL`) |
| E1 결제자 중복 0 | 질의 + 파일 검사 | 결제자별 `GROUP BY`, 내보낸 뒤 행 수 검사 |

#### 7. 검증

**11월 결제 다시 계산하기.** 콘셉트 문서를 그대로 읽은 기준(크기·주기 맞춤, a1~a3, 건너뛰기와 배송 실패는 받지 않은 것)으로 행마다 계산해 엑셀과 견주면, 차이가 나거나 계산할 수 없는 행은 다섯입니다.

| 번호 | 이름 | 기록 | 계산 | 차이 | 원인 |
| --- | --- | --- | --- | --- | --- |
| 4 | 김서연 | 100,000 | 75,000 | +25,000 | 11/12 건너뛰기를 결제에 반영하지 않음 |
| 7 | 노은서 | 96,000 | 128,000 | -32,000 | 건너뛰기 11/13은 금요일이라 배송일이 아님. 운영자는 11/12로 읽고 한 회를 뺀 것으로 보임 |
| 9 | 문예린 | 84,000 | 72,000 | +12,000 | 지역 밖 배송비 4회 × 3,000원. 콘셉트 문서에 없는 요금(q3) |
| 21 | 유채원 | 60,000 | 64,000 | -4,000 | 격주 홀수 주 2회 × 32,000원 = 64,000원. 입력 실수로 보임 |
| 27 | 전하은 | 72,000 | 계산 불가 | — | 시작일 없음 |

행 단위로는 맞아 보이지만 **사람 단위로 보면** 틀린 곳이 하나 더 있어요. 10번과 11번은 박서준 한 사람이고, 11번은 이사입니다. 한 주에 꾸러미 하나를 받았으니 11월 결제는 4회 × 18,000원 = 72,000원이어야 하는데, 엑셀은 72,000원 + 36,000원 = 108,000원을 받았습니다. 36,000원을 더 받은 거예요. 행별 계산으로는 이것을 찾을 수 없습니다. 2번 과제에서 같은 연락처를 같은 구독자로 맞춘 결정이 이 오류를 찾게 해 줬어요.

30번 최서윤은 11/19 배송 실패로 받은 꾸러미가 3개이고, 3 × 32,000원 = 96,000원이 기록과 같습니다. 콘셉트 문서 3번의 "받은 꾸러미 수만큼"을 배송 결과로 읽은 해석과 운영자의 실제 처리가 맞아요. 그래서 배송 실패(F5)는 개념 스키마의 사실이어야 합니다.

**인구 왕복.** 2번의 맞추기 결정대로 SQLite에 넣었습니다. 9번(지역 밖)과 27번(시작일 없음)은 q로 남겨 넣지 않았고, 11번은 10번 구독자의 두 번째 주소 기간으로 넣었으며, 7번의 11/13 건너뛰기는 배송일이 아니라 넣지 않았어요. 23번은 결제자를 이수진(새 구독자)으로 넣었습니다. 결과는 구독 27개, 결제 합계 1,947,000원이고, 구독마다 SQL 결제 질의의 값과 파이썬 계산이 모두 같았습니다. 박서준의 결제는 72,000원으로 나와 위의 사람 단위 판단과 같아요.

합계도 맞춰 봅니다. 엑셀 기록 합계는 2,128,000원(30행)이에요. 여기서 넣지 않은 9·11·27번의 기록 84,000 + 36,000 + 72,000 = 192,000원을 빼면 1,936,000원입니다. 이 값과 SQLite 합계 1,947,000원은 11,000원 차이가 나는데, 위 표에서 SQLite에 넣은 행의 차이만 더하면 같은 값이 나와요. 4번 +25,000(기록이 많음)을 빼고, 7번 -32,000과 21번 -4,000(기록이 적음)을 더하면 1,936,000 - 25,000 + 32,000 + 4,000 = 1,947,000원입니다.

**반례 시험.** 여덟 사례 모두 기대대로 나왔습니다.

| 사례 | 기대 | 결과 |
| --- | --- | --- |
| 11-12 회차를 11-08(일) 23:59에 건너뜀 | 받아들임 | 받아들임 |
| 11-19 회차를 11-16(월) 00:00에 건너뜀 | 거부 | 거부 (R2 CHECK) |
| 11-13(금)을 건너뜀 | 거부 | 거부 (외래 키: 배송일 아님) |
| 이미 건너뛴 회차를 또 건너뜀 | 받아들임, 바뀐 행 0 | 받아들임, 바뀐 행 0 |
| 크기 "중간"으로 구독 | 거부 | 거부 (외래 키) |
| 격주인데 주차 없음 | 거부 | 거부 (R1 CHECK) |
| 한 구독자에게 겹치는 둘째 구독 | 거부 | 거부 (R4 트리거) |
| 북구 주소 | 거부 | 거부 (R3 CHECK) |

여기에 풀이를 만들며 실제로 겪은 일을 적어 둡니다. 처음 실행한 시험에서는 넷이 기대와 달랐어요. 마감 뒤 건너뛰기와 금요일 건너뛰기가 **받아들여졌고**, 크기 "중간"과 주기 없는 격주는 거부되긴 했지만 엉뚱한 제약(겹치는 구독)에 걸려서였습니다. 원인은 셋이었습니다.

```text
1. 마감 검사를 requested_at < datetime(delivery_date, '-3 days') 로 씀
   '2026-11-16 00:00' < '2026-11-16 00:00:00' 이 참 → 짧은 문자열이 앞서서 마감 시각을 통과
   → julianday 로 바꿔 시각으로 견줌
2. SQLite 는 외래 키 검사가 기본으로 꺼져 있음 → PRAGMA foreign_keys = ON
3. 시험용 구독을 이미 구독이 있는 S01 로 넣음 → 겹침 트리거가 먼저 거부
   → 구독이 없는 시험용 구독자로 바꿔, 확인하려는 제약 하나만 걸리게 함
```

마지막 원인이 특히 배울 만합니다. 반례 시험은 "거부되었다"만 보면 안 되고 **무엇 때문에** 거부되었는지까지 봐야 해요. 엉뚱한 이유로 거부된 시험은 그 규칙을 시험하지 않은 것과 같습니다.

#### 다른 답이 가능한 곳

- a3 대신 "그 전 주 일요일"(11일 전)로 가정해도 됩니다. 그때는 반례 시험의 마감 사례 날짜가 바뀌고, 지금 엑셀의 건너뛰기 가운데 마감을 넘긴 것이 있는지 다시 봐야 합니다(엑셀에는 요청 시각이 없어 확인할 수 없음).
- 10·11번을 구독 둘로 보고 10번에 종료일 11-15를 주는 설계도 가능합니다. 결제는 같은 72,000원이 나오지만, "한 사람이 구독을 둘 가질 수 있는가"(q6)에 답을 미리 정해 버리는 셈이라 근거를 적어야 합니다.
- 9번을 넣고 "지역 밖 배송비" 사실을 더하는 설계도 가능합니다. 운영자가 q3에 "외곽은 3천원 더 받고 보낸다"고 답했다면 그쪽이 맞아요. 그때 R3은 "배송 지역 = 기본 지역 + 외곽 지역"으로 바뀝니다.
- V2의 필요량을 꾸러미 구성 확정(F6) 뒤의 실제 구성으로 계산해도 됩니다. 이 풀이는 농부 메모의 양(m2, m4)으로 "예상"을 계산했습니다.
