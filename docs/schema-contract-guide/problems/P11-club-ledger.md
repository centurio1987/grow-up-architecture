## P11 동아리 회비 장부 — 스프레드시트에서

| 난이도 | 씨앗 형식 | 중심 산출물 | 연결 장 |
| --- | --- | --- | --- |
| 중 | 손으로 만든 스프레드시트 | 구조 복원·개념 스키마·내부 스키마 | 21, 23 |

### 상황

대학 노래 동아리 「소리모아」의 총무가 한 학기 회비를 엑셀로 관리해 왔습니다. 다음 학기부터 총무가 바뀌는데, 새 총무는 엑셀 대신 작은 웹 앱을 쓰고 싶어 해요. 지금 총무가 넘겨준 것은 이 시트 하나와 짧은 설명뿐입니다.

> "노란 칸은 면제예요. 빨간 글씨는 덜 낸 거고요. 비고에 적힌 대로예요."

### 주어진 자료

`problems/data/p11-club-ledger.csv`의 전문입니다. 엑셀에서 CSV로 내보내면서 색이 사라졌으므로, 색은 아래에 따로 적었습니다.

```text

이름,학번,연락처,3월,,4월,5월,,비고
,,,회비,MT,회비,회비,축제,
김가은,20231234,010-1111-2222,10000,30000,10000,10000,5000,
이나래,20221111,010-3333-4444,10000,30000,면제,,,4월 휴학
박다솜,20241001,010-5555-6666,10000,,10000,10000,5000,MT 불참
정마루,2023-5678,010 7777 8888,10000,30000,10000,5000,5000,5월 회비 5천 덜 냄
최라온,20245555,01099990000,,,10000,10000,5000,4월 가입
이나래,20221111,010-3333-9999,,,,10000,5000,복학

```

```text
색 (원본 엑셀)
  이나래 첫 줄의 4월 회비 칸: 노란색
  정마루의 5월 회비 칸: 빨간 글씨
```

### 과제

1. 23장의 순서로 표의 구조를 되살리세요. 실제 열이 몇 개인지, 사실 후보가 몇 개인지 세고, 합계 줄을 검산합니다.
2. 같은 사람으로 보이는 줄과 형식이 다른 식별자를 찾아 식별 규칙을 정하세요.
3. 빈칸과 특별한 값(면제, 덜 냄)의 뜻을 정하고, 자료만으로 정할 수 없는 것은 질문으로 남기세요.
4. 개념 스키마를 쓰세요. 회원의 활동 상태(휴학·복학·가입)를 기록할 자리를 포함합니다.
5. 내부 스키마(DDL)를 쓰고, 이 시트를 정제 규칙대로 옮겨 넣으면 몇 행이 되는지 SQLite로 확인하세요.

### 실마리

- 머리글이 두 줄이고 월 이름이 병합 칸입니다.
- 이나래는 두 번 나옵니다. 학번이 같고 연락처가 다릅니다.
- 같은 빈칸이라도 줄과 비고에 따라 뜻이 다릅니다.
- 합계 줄은 사실이 아니라 검산 거리입니다(23장).

### 풀이

숫자는 `verification/check_p11_p13_p14.py`의 출력(`verification/p11-p13-p14-result.json`)과 `verification/check_part4_ddl.py`의 출력(`verification/part4-ddl-result.json`)에서 옮겼습니다.

#### 1. 구조 되살리기

```text
1. 표 밖의 것       제목 줄 "소리모아 2026년 1학기 회비 장부" 를 뗌
2. 머리글 줄 수     2줄 (월 / 항목)
3. 병합 칸 채우기    "3월" 오른쪽 빈칸 → 3월, "5월" 오른쪽 빈칸 → 5월
4. 실제 열          3월 회비 · 3월 MT · 4월 회비 · 5월 회비 · 5월 축제     → 5개
5. 세로로 펴기       (이름, 학번, 월, 항목, 칸 값) 으로, 빈칸은 행으로 만들지 않음
                   → 사실 후보 22개 (회원 줄 6줄)
6. 합계 줄 떼고 검산
```

합계 줄을 계산과 견주면 한 열이 다릅니다.

| 열 | 계산(숫자 칸만) | 합계 줄 | 같은가 |
| --- | --- | --- | --- |
| 3월 회비 | 40,000 | 40,000 | 예 |
| 3월 MT | 90,000 | 90,000 | 예 |
| 4월 회비 | **40,000** | **30,000** | 아니오 |
| 5월 회비 | 45,000 | 45,000 | 예 |
| 5월 축제 | 25,000 | 25,000 | 예 |

4월 회비 칸의 숫자는 김가은·박다솜·정마루·최라온의 10,000원 네 개라서 40,000원입니다. 합계 줄은 30,000원이에요. 최라온이 4월에 가입했다(비고)는 점을 보면, 총무가 합계 식을 최라온의 줄을 넣기 전에 만들었고 줄을 더한 뒤 식을 고치지 않았을 가능성이 있어요. 원장에는 추측이 아니라 사실과 질문으로 적습니다.

```text
f  4월 회비 숫자 칸의 합은 40,000원, 합계 줄은 30,000원        근거: 관찰(계산)
q  4월 회비 합계 30,000원은 어느 회원을 뺀 값인가요? 실제로 걷힌 금액은 얼마인가요?
```

#### 2. 식별 규칙

하이픈을 지운 학번으로 세면 `20221111`이 두 줄입니다(이나래). 하이픈이 든 학번은 `2023-5678` 하나예요(정마루). 연락처도 세 가지 꼴(`010-1111-2222`, `010 7777 8888`, `01099990000`)이 섞여 있습니다.

```text
식별 규칙   회원은 학번으로 식별한다. 학번은 숫자 8자리로 맞춘다(하이픈·공백 제거)
           → 6줄이 회원 5명이 됨
연락처     숫자만 남겨 저장하고, 보여 줄 때 하이픈을 넣는다 (외부 스키마의 모양)
이나래 두 줄 같은 학번, 연락처 다름 → 한 사람. 연락처는 나중 줄(복학 뒤) 것을 지금 연락처로
           → 가정. 옛 번호를 남겨야 하는지는 q
```

이름으로 식별하지 않는 이유는 8장과 같아요. 동명이인이 있을 수 있고, 이 시트에서도 이나래가 두 줄인 것은 이름 때문이 아니라 학번이 같기 때문에 같은 사람이라고 판단할 수 있습니다.

#### 3. 빈칸과 특별한 값

금액 칸의 값은 `10000`, `30000`, `5000`, `면제` 네 가지입니다. 숫자가 아닌 칸은 이나래 4월 회비의 `면제` 하나예요. 빈칸의 뜻은 줄과 비고에 따라 다릅니다.

| 빈칸 | 비고·맥락 | 뜻 | 옮기는 법 |
| --- | --- | --- | --- |
| 박다솜 3월 MT | "MT 불참" | 참가하지 않음 | 행 없음. 미납이 아님 |
| 최라온 3월 회비·MT | "4월 가입" | 가입 전 | 행 없음. 활동 시작을 4월로 기록 |
| 이나래 첫 줄 5월 | 둘째 줄에 5월이 있음 | 이 줄의 기간이 아님 | 행 없음(둘째 줄이 채움) |
| 이나래 둘째 줄 3·4월 | "복학" | 이 줄의 기간이 아님 | 행 없음 |
| 김가은 비고 | 비어 있음 | 특이 사항 없음 | — |

특별한 값은 이렇게 다룹니다.

```text
면제 (노란 칸)    납부가 아니라 "면제" 라는 다른 사실. 금액 0 으로 적지 않음
                  → 면제 사실 (회원, 월, 사유)
덜 냄 (빨간 글씨)  정마루 5월 회비 5,000원. 낸 금액은 5,000원이라는 사실
                  → 납부 사실 (회원, 월, 5000). 덜 냈다는 것은 청구액과 견줘 계산(파생)
```

면제를 금액 0으로 적으면 "0원을 냈다"와 "낼 필요가 없다"가 구별되지 않아요. 이나래가 4월에 휴학했으니 면제는 휴학 때문으로 보이지만, 휴학하면 늘 면제인지는 자료만으로는 모릅니다.

```text
q  휴학한 달은 늘 면제인가요, 신청해야 면제인가요?
q  덜 낸 5,000원은 다음 달에 받나요? 받으면 어느 달 회비로 기록하나요?
q  회비는 늘 월 10,000원인가요? 가입한 달도 다 내나요?
q  MT·축제 참가비는 참가 신청한 사람만 내나요? 신청하고 안 낸 사람도 있나요?
```

#### 4. 개념 스키마

```text
[개체] 회원(학번 8자리)
[개체] 행사(행사 번호)                 MT(2026-03, 30,000원), 축제(2026-05, 5,000원)
[값]   월(YYYY-MM) · 원 · 활동 상태{활동, 휴학}

[사실] F1 회원 은 이름 을 가진다
[사실] F2 회원 은 지금 연락처 를 가진다              (옛 연락처 보관 여부는 q)
[사실] F3 회원 은 [시작 월부터] 활동 상태 에 있다     (여럿: 3월 활동, 4월 휴학, 5월 활동)
[사실] F4 회원 이 월 의 회비 로 금액 을 냈다          (회원·월 마다 많아야 하나)
[사실] F5 회원 은 월 의 회비 를 면제받았다 (사유)
[사실] F6 행사 는 월 과 참가비 를 가진다
[사실] F7 회원 이 행사 참가비 로 금액 을 냈다         (있으면 참가로 봄 — q)

[제약] R1 같은 회원·같은 월에 회비 납부와 면제가 함께 있지 않음
[제약] R2 회비 납부는 그 달에 활동 상태인 회원만 (휴학 달은 납부 없음 — q)
[파생] D1 덜 낸 금액 = 그 달 청구 회비(10,000원, q) - 낸 금액
[파생] D2 월 회비 합계 = 그 달 F4 금액의 합                   ← 합계 줄을 대신함
```

F3이 활동 상태를 **기간이 있는 사실**로 두는 것은 9장의 등급 이력과 같은 생각입니다. 이나래의 두 줄은 서로 다른 사람이 아니라, 같은 사람의 서로 다른 기간을 총무가 줄로 나눠 적은 것이었어요.

#### 5. 내부 스키마와 옮겨 넣기

```sql
CREATE TABLE member (
  student_id TEXT PRIMARY KEY CHECK (length(student_id) = 8 AND student_id GLOB '[0-9]*'),
  name TEXT NOT NULL,
  phone TEXT
);
CREATE TABLE member_status (
  student_id TEXT NOT NULL REFERENCES member(student_id),
  from_month TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('활동','휴학')),
  PRIMARY KEY (student_id, from_month)
);
CREATE TABLE event (
  event_id TEXT PRIMARY KEY, month TEXT NOT NULL, name TEXT NOT NULL,
  fee INTEGER NOT NULL CHECK (fee >= 0)
);
CREATE TABLE dues_payment (
  student_id TEXT NOT NULL REFERENCES member(student_id),
  month TEXT NOT NULL,
  amount INTEGER NOT NULL CHECK (amount > 0),
  PRIMARY KEY (student_id, month)
);
CREATE TABLE dues_exemption (
  student_id TEXT NOT NULL REFERENCES member(student_id),
  month TEXT NOT NULL,
  reason TEXT,
  PRIMARY KEY (student_id, month)
);
CREATE TABLE event_payment (
  student_id TEXT NOT NULL REFERENCES member(student_id),
  event_id TEXT NOT NULL REFERENCES event(event_id),
  amount INTEGER NOT NULL CHECK (amount > 0),
  PRIMARY KEY (student_id, event_id)
);
```

정제 규칙(학번 하이픈 제거, 같은 학번은 한 사람, `면제`는 면제 표로, 빈칸은 행 없음)대로 SQLite에 옮겨 넣은 결과입니다(SQLite 3.53.0).

```text
회원 5명 · 회비 납부 13행 · 면제 1행 · 행사 납부 8행     (13 + 1 + 8 = 22 = 사실 후보 수)
월별 회비 합   2026-03 40,000 · 2026-04 40,000 · 2026-05 45,000
행사별 합      MT 90,000 · 축제 25,000
덜 낸 회비     20235678(정마루) 2026-05 5,000원
같은 학번·같은 달 회비를 한 번 더 넣으면 → 기본 키가 거부 (UNIQUE constraint failed)
```

사실 후보 22개가 세 표의 22행으로 빠짐없이 옮겨졌습니다. 4월 회비 합은 표에서 계산하면 40,000원이고, 시트의 합계 줄 30,000원과는 여전히 다릅니다. 표는 합계를 저장하지 않으니 이 차이는 질문(1번의 q)으로만 남아요.

R1(납부와 면제가 함께 있지 않음)은 이 DDL이 지키지 않습니다. 두 표에 같은 회원·같은 달 행이 각각 들어갈 수 있으니까요. 보장 위치표에 "응용(면제를 넣을 때 납부 확인) + 감시 질의"로 적거나, 납부와 면제를 한 표(`dues_record`의 종류 열)로 합쳐 기본 키 하나로 지키는 방법이 있습니다.

#### 다른 답이 가능한 곳

- 회비 청구를 사실로 두는 설계도 가능합니다. "그 달 청구액" 표를 만들면 D1(덜 낸 금액)을 청구 - 납부로 바로 계산할 수 있고, 회비가 월마다 다를 때도 맞습니다. 이 시트에는 청구액이 없어서 원장에서는 q로 남겼습니다.
- 행사 참가를 납부와 따로 두는 설계도 가능합니다. 참가했는데 아직 안 낸 사람이 있다면(q) 참가 표가 필요합니다.
- 연락처 이력을 남기는 설계도 가능합니다. 이나래의 옛 번호를 지울지는 개인정보를 얼마나 보관할지 정하는 문제라서 동아리가 판단해야 합니다.

#### 흔한 실수

- 시트를 그대로 표로 옮겨 `mar_dues`, `mar_mt`, `apr_dues` … 같은 열을 만드는 것. 다음 학기에 열을 다시 만들어야 합니다(23장의 반복 열).
- 이나래를 두 회원으로 등록하는 것. 학번이 같으면 같은 사람입니다.
- `면제`를 0원 납부로 적는 것. 0원 납부와 면제는 다른 사실입니다.
- 합계 줄을 표에 저장하는 것. 파생 값이고, 이 시트에서는 틀리기까지 했습니다.
- 정마루의 5,000원을 미납 5,000원으로 바꿔 적는 것. 자료가 말하는 것은 5,000원을 **냈다**는 사실이고, 얼마를 덜 냈는지는 청구액을 알아야 계산됩니다.
