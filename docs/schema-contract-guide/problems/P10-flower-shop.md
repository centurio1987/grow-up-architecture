## P10 동네 꽃집의 주문 — 메신저 대화에서

| 난이도 | 씨앗 형식 | 중심 산출물 | 연결 장 |
| --- | --- | --- | --- |
| 중 | 메신저 대화 + 메모장 | 원장·질문 목록·개념 스키마 초안 | 21, 22 |

### 상황

동네 꽃집 「봄날」의 사장님은 주문을 메신저로 받습니다. 손님이 늘면서 주문을 놓치는 일이 생겨, 간단한 주문 관리 앱을 만들기로 했어요. 사장님이 휴대폰에서 대화 두 방과 메모장을 내보내 줬습니다. 설계에 쓸 자료는 이것뿐이고, 사장님은 바빠서 질문은 한 번에 모아서 받겠다고 합니다.

### 주어진 자료

`problems/data/p10-flower-chat.txt`의 전문입니다. 발화 번호(m1, h1, n1 …)는 이 자료에서 출처로 씁니다.

```text
[대화방 1: 손님 "민지"]
m1  11/14 10:02 민지: 사장님 안녕하세요! 담주 화욜 엄마 생신이라 꽃다발 하나 주문하고 싶어요
m2  11/14 10:05 사장: 네~ 예산 어느정도 생각하세요?
m3  11/14 10:06 민지: 5만원 정도요? 분홍 계열로요
m4  11/14 10:06 민지: (사진) 이런 느낌이요!!
m5  11/14 10:09 사장: 이쁘네요 ㅎㅎ 5만원이면 이 크기는 어렵고 비슷한 느낌으로 해드릴게요
m6  11/14 10:10 민지: 넵 좋아요 리본에 "엄마 사랑해요" 써주세요
m7  11/14 10:11 사장: 배달인가요 픽업인가요?
m8  11/14 10:12 민지: 배달이요 성수동 한빛아파트 101동 1203호 오후 3시쯤 받으실수 있어요
m9  11/14 10:13 사장: 배달비 3천원 추가고요 5만3천원 입금해주시면 돼요 (계좌번호)
m10 11/14 10:30 민지: 입금했어요!
m11 11/17 09:40 민지: 사장님 죄송한데 혹시 수욜로 바꿀수 있을까요? 엄마가 화욜에 집에 안계신대요ㅠ
m12 11/17 09:52 사장: 네 수요일 같은 시간으로 바꿔둘게요
m13 11/17 09:53 민지: 감사합니다ㅠㅠ 리본 문구는 그대로요!

[대화방 2: 손님 "한결건축 총무님"]
h1  11/10 08:55 총무: 사장님 이번주도 월욜 사무실 꽃 부탁드려요
h2  11/10 08:57 사장: 네 늘 하던대로 로비 화병이랑 회의실 작은거 두개요?
h3  11/10 08:58 총무: 네네 근데 이번주는 회의실 거 하나만요
h4  11/10 09:01 사장: ㅇㅋ 그럼 이번주는 6만원요. 월말에 한번에 계산서 끊어드릴게요
h5  11/17 08:50 총무: 사장님 담주부터 2주는 사무실 공사라 꽃 쉬어요
h6  11/17 08:51 총무: 아 그리고 계산서 받을 메일 바뀌었어요 (사진)
h7  11/17 08:53 사장: 넵 확인했습니다~

[사장 메모장]
n1  정기: 한결건축 월 로비 4만 + 회의실 소 2만x2 = 8만/주, 월말 계산서
n2  배달비 성수·송정 3천, 그 외 5천
n3  당일 주문은 오전 11시까지
```

### 과제

1. 자료를 추출 원장(7장)으로 옮기세요. 칸마다 적어도 세 줄씩, 줄마다 출처와 근거 수준을 붙입니다.
2. 용어집을 만드세요. 대화에서 같은 것을 다르게 부르거나, 다른 것을 같은 말로 부르는 곳을 찾아 묶습니다.
3. 22장의 방법으로 모호한 말을 찾아, 사장님이 한 번에 답할 수 있는 질문 목록(여섯 개 이상)으로 바꾸세요. 질문마다 그 답이 설계의 무엇을 바꾸는지 적습니다.
4. 개념 스키마 초안을 2장의 표기로 쓰세요. 아직 답을 모르는 곳은 가정으로 표시합니다.
5. 사장님이 아침마다 보는 "오늘 할 일" 외부 스키마를 3장의 다섯 항목으로 쓰세요.

### 실마리

- 주문한 사람과 꽃을 받는 사람이 같지 않을 수 있습니다(m1, m8).
- 이 꽃집의 상품은 정해진 목록이 아니라 그때그때 만드는 것일 수 있습니다(m3~m5).
- 정기 주문과 그 주의 예외(h2~h3), 쉬는 기간(h5)을 따로 생각해 보세요.
- 결제 방식이 손님마다 다릅니다(m9~m10, h4).
- 메모장(n1~n3)은 대화보다 정리된 진술이지만, 대화와 맞는지 확인해야 합니다.

### 풀이

#### 1. 추출 원장

근거 수준은 모두 **진술**입니다. 사장님과 손님이 말한 것이고, 업무 규칙으로 확인받은 것은 없어요. 메모장(n)은 사장님이 스스로 정리한 진술로 봅니다.

| 줄 | 칸 | 내용 | 출처 |
| --- | --- | --- | --- |
| t1 | T | 꽃다발: 손에 들고 가는 꽃 묶음. 이 자료에서는 주문 제작 | m1, m5 |
| t2 | T | 정기 / "늘 하던대로": 매주 같은 요일·같은 구성의 주문 | h1, h2, n1 |
| t3 | T | 회의실 작은거 = 회의실 소(작은 크기) | h2, n1 |
| t4 | T | 픽업 / 배달: 받는 방법 두 가지 | m7 |
| t5 | T | 계산서: 월말에 한 번 발행하는 세금계산서로 보임(확인 필요) | h4, n1 |
| f1 | F | 손님 민지가 11/14에 꽃다발 하나를 주문했다. 예산 5만원, 분홍 계열, 참고 사진 있음 | m1~m5 |
| f2 | F | 그 주문의 리본 문구는 "엄마 사랑해요" | m6, m13 |
| f3 | F | 그 주문은 성수동 한빛아파트 101동 1203호로 오후 3시쯤 배달 | m8 |
| f4 | F | 그 주문의 금액은 꽃 5만원 + 배달비 3천원 = 5만3천원, 11/14 입금됨 | m9, m10 |
| f5 | F | 그 주문의 배달일이 화요일에서 수요일로 바뀌었다(같은 시간) | m11, m12 |
| f6 | F | 한결건축은 매주 월요일 로비 화병 1개 + 회의실 소 2개를 받는다. 주당 8만원 | h2, n1 |
| f7 | F | 11/10 주는 회의실 소 1개만, 6만원 | h3, h4 |
| f8 | F | 11/24 주부터 2주는 쉰다 | h5 |
| f9 | F | 한결건축의 계산서 받을 메일이 바뀌었다(새 주소는 사진) | h6 |
| v1 | V | 사장님은 날짜별로 만들 꽃과 배달할 곳을 봐야 한다(주문을 놓치지 않으려고) | 상황 |
| v2 | V | 사장님은 월말에 법인 손님별 계산서 금액을 봐야 한다 | h4, n1 |
| c1 | C | 손님이 주문한다(대화로) | m1, h1 |
| c2 | C | 손님이 배달일을 바꾼다 | m11 |
| c3 | C | 손님이 입금한다 / 사장님이 입금을 확인한다 | m9, m10 |
| c4 | C | 정기 주문의 이번 회차 구성을 바꾼다 | h3 |
| c5 | C | 정기 주문을 몇 주 쉰다 | h5 |
| r1 | R | 배달비: 성수·송정 3천원, 그 밖 5천원 | n2, m9 |
| r2 | R | 당일 주문은 오전 11시까지 | n3 |
| r3 | R | 개인 손님은 선입금, 법인 정기 손님은 월말 계산서 | m9, h4 |
| r4 | R | 정기 구성 단가: 로비 4만, 회의실 소 2만 | n1 |

m9의 배달비 3천원이 n2의 "성수 3천"과 맞는다는 것, h4의 6만원이 n1의 단가로 계산한 4만 + 2만 × 1과 맞는다는 것은 자료끼리의 검산입니다. 맞는다고 규칙이 확인되는 것은 아니지만, 어긋났다면 바로 질문거리가 되었을 거예요.

#### 2. 용어집

```text
꽃다발 (m1)                 주문 제작 상품. 크기·색·예산으로 정함
꽃 / 사무실 꽃 (h1)          정기 주문 한 회차 전체를 가리킴
로비 화병, 회의실 작은거,      정기 주문의 구성 항목. "작은거" = "소"
회의실 소 (h2, n1)
주문한 사람 / 받는 사람       민지(주문) ≠ 엄마(받음). 이름이 다른 두 사람
총무님 / 한결건축             손님은 회사, 연락하는 사람은 총무. 둘을 구분
계산서 / 입금                서로 다른 결제 방식 (r3)
```

동음이의처럼 보이는 것은 "꽃"입니다. 민지에게 꽃은 상품 하나(꽃다발)이고, 총무님에게 "사무실 꽃"은 정기 주문의 한 회차예요. 이음동의어는 "회의실 작은거"와 "회의실 소"입니다. 10장의 이름 충돌을 대화 안에서 미리 정리해 두는 셈이에요.

#### 3. 질문 목록

사장님이 한 번에 답할 수 있게, 선택지나 사례를 달라는 꼴로 썼습니다.

| 번호 | 질문 | 바뀌는 것 |
| --- | --- | --- |
| q1 | "오후 3시쯤"처럼 시간을 받으면, 배달은 정한 시각인가요, 시간대(예: 2~4시)인가요? | 배달 사실의 꼴(시각 하나 / 구간), 오늘 할 일 외부 스키마의 정렬 |
| q2 | 상품은 정해진 메뉴가 있나요, 늘 주문마다 만드나요? 메뉴가 있다면 가격표를 받을 수 있나요? | 상품을 개체(목록)로 둘지, 주문 항목의 속성(예산·색·사진)으로 둘지 |
| q3 | 지난달 날짜를 바꾼 주문은 몇 건이었고, 바꾼 기록을 남겨 두시나요? | 변경 이력을 사실로 둘지, 지금 배달일만 둘지 |
| q4 | 정기 주문에서 "이번 주만 다르게"는 한 달에 몇 번쯤 있나요? 그 주의 금액은 늘 단가로 다시 계산하나요? | 정기 계약과 회차를 나누는 구조, 회차 금액의 계산 규칙 |
| q5 | "2주 쉬어요"처럼 쉬는 주에는 계산서에서 빠지나요? 쉬는 기간을 미리 알려 주지 않고 빠진 적이 있나요? | 쉬는 기간 사실, 계산서 금액 계산 |
| q6 | 배달비 "그 외 5천"에 상한이 있나요? 아주 먼 곳은 안 가시나요? | r1의 꼴, 주문 받기의 사전조건 |
| q7 | 오전 11시가 지난 당일 주문은 거절하시나요, 다음 날로 넘기시나요? | r2를 사전조건으로 둘지, 배달일 조정 규칙으로 둘지 |
| q8 | 입금이 확인되지 않은 주문도 만드시나요? 언제까지 기다리시나요? | 주문 상태(입금 대기 / 확정)와 그 전이 |
| q9 | 계산서는 세금계산서인가요? 받을 메일 말고 사업자 정보도 필요한가요? | 법인 손님의 사실 유형 |

q3과 q4는 22장에서 본 대로 규칙이 아니라 **지난 사례**를 묻습니다. 규칙으로 물으면 "보통 안 바꿔요"처럼 답하기 쉽지만, 지난달 건수를 물으면 실제가 나와요.

#### 4. 개념 스키마 초안

```text
[개체] 손님(손님 번호)                     ← 대화방 이름은 바뀔 수 있으므로 번호를 새로 붙임
[개체] 주문(주문 번호)
[개체] 정기 계약(계약 번호)
[값]   받는 방법{배달, 픽업} · 결제 방식{선입금, 월말 계산서} · 원

[사실] F1 손님 은 이름 과 연락 경로 를 가진다
[사실] F2 손님 은 결제 방식 을 가진다                      (r3, 가정: 손님마다 하나)
[사실] F3 주문 은 손님 이 한 것이다
[사실] F4 주문 은 받는 날 을 가진다                         (f5: 바뀔 수 있음, 이력은 q3 답 전까지 두지 않음)
[사실] F5 주문 은 받는 방법 을 가진다
[사실] F6 배달 주문 은 받는 곳 과 받는 시간 을 가진다       (시간의 꼴은 q1)
[사실] F7 주문 은 항목 을 가진다 (여럿)
         항목: 종류(꽃다발, 로비 화병, 회의실 소 ...), 예산 또는 단가, 색, 참고 사진, 리본 문구(선택)
[사실] F8 주문 은 입금 확인 시각 을 가진다 (선입금 손님만)
[사실] F9 정기 계약 은 손님, 요일, 기본 구성(항목과 단가) 을 가진다
[사실] F10 정기 계약 은 쉬는 기간 [시작일, 끝일) 을 가진다 (여럿)
[사실] F11 정기 계약 의 회차 는 주문 이다                    ← 회차마다 주문 하나를 만듦(가정)

[제약] R1 배달비 = 받는 곳이 성수·송정이면 3,000원, 그 밖은 5,000원 (q6 확인 전)
[제약] R2 받는 날이 주문한 날과 같으면 주문 시각은 11:00 이전 (q7 확인 전)
[제약] R3 결제 방식이 선입금이면, 입금 확인 전에는 만들지 않음 (q8 확인 전)
[파생] D1 주문 금액 = 항목 금액 합 + 배달비
[파생] D2 월 계산서 금액 = 그 달 회차 주문 금액의 합 (쉬는 회차 제외)
```

F11이 이 초안의 중심 결정입니다. 정기 주문을 "계약"과 "회차"로 나누고, 회차마다 보통 주문을 하나 만든다고 가정했어요. 그러면 h3의 "이번 주만 회의실 하나"는 그 회차 주문의 항목을 고치는 일이 되고, 계약의 기본 구성은 그대로 남습니다. 회차를 따로 만들지 않고 계약에서 금액을 계산하면, 예외가 있던 주(h3)의 6만원을 기록할 곳이 없어요.

받는 사람(엄마)의 이름은 대화에 없어서 사실 유형으로 두지 않았습니다. 배달 기사가 받는 사람을 불러야 한다면 필요할 수 있으니, 질문 목록에 더할 후보예요.

#### 5. 외부 스키마 "오늘 할 일"

```text
[외부] V1 오늘 할 일                      이용자: 사장님 (아침, 휴대폰)
  행      받는 날이 오늘인 주문 하나 (정기 회차 포함, 쉬는 회차 제외)
  열      받는 시간 ← F6 · 받는 방법 ← F5 · 손님 이름 ← F3 → F1
          · 항목 요약 ← F7 (종류 × 개수, 색) · 리본 문구 ← F7
          · 받는 곳 ← F6 (배달만) · 결제 상태 ← F2 + F8 ("입금 확인" / "계산서" / "입금 대기")
  고르기   F4 = 오늘, 쉬는 기간이 아님(F10)
  순서     받는 시간 순, 시간 없는 픽업은 맨 뒤
  가림     없음
  갱신     읽기 전용. 만들기 완료·배달 완료 표시는 명령으로 (계약은 이후 단계)
```

"결제 상태" 열이 입금 대기인 주문을 눈에 띄게 하면, q8의 답이 "입금 전에는 안 만든다"일 때 사장님이 실수로 만드는 일을 막을 수 있어요. 외부 스키마가 규칙을 지키는 자리 하나가 되는 셈이라, 12장의 보장 위치표에 "R3 · 응용(오늘 할 일 화면의 표시)"로 적을 수 있습니다. 다만 화면 표시는 사람이 무시할 수 있으니 약한 보장이라는 점도 함께 적어요.

#### 다른 답이 가능한 곳

- 정기 주문을 회차마다 주문으로 만들지 않고, 계약 + 예외 기록(그 주의 바뀐 구성)으로 두는 설계도 가능합니다. 예외가 드물다면(q4) 이쪽이 단순합니다.
- 상품 목록을 두는 설계도 가능합니다. q2의 답이 "메뉴가 있다"면 항목의 종류는 상품 목록을 가리키는 외래 키가 됩니다.
- 손님을 개인·법인 하위 유형으로 나눌 수도 있습니다. 결제 방식이 손님 종류로 정해진다면 하위 유형이 자연스럽고, 법인인데 선입금하는 손님이 있다면 결제 방식을 따로 두는 편이 낫습니다(12장의 하위 유형 판단).

#### 흔한 실수

- "엄마"를 손님으로 등록하는 것. 주문한 사람과 받는 사람은 다릅니다.
- m11~m12의 날짜 변경을 새 주문으로 적는 것. 같은 주문의 받는 날이 바뀐 것이고, 입금(f4)은 그대로 이어져야 합니다.
- 메모장 n1의 "8만/주"를 정기 계약의 금액 사실로 저장하는 것. 단가에서 계산되는 값이라 D2처럼 파생으로 둡니다(4장의 단일 조건).
- 사진(m4, h6)을 무시하는 것. 참고 사진은 주문 항목의 일부이고, h6의 사진에는 바뀐 메일 주소가 있습니다. 자료에 없는 정보가 사진에 있다는 사실을 원장에 남겨야 합니다.
