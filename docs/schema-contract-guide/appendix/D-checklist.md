## D. 설계 검사표

설계를 마쳤다고 말하기 전에 확인할 질문을 모았습니다. 먼저 13장의 여덟 질문으로 전체가 맞물리는지 보고, 그다음 단계마다 빠뜨리기 쉬운 것을 봐요. 질문마다 "어디서 확인하는가"를 붙였습니다. 답이 "예"인데 그 근거를 가리킬 수 없다면, 아직 "예"가 아닙니다.

### 맞물림 여덟 질문

| 번호 | 질문 | 어디서 확인 |
| --- | --- | --- |
| 1 | 원장의 모든 f가 개념 스키마의 사실 유형이 되었는가 | 추적표의 개념 열 |
| 2 | 개념 스키마의 모든 사실 유형이 내부 스키마 어딘가에 기록되는가 | 개념-내부 사상표(6장) |
| 3 | 외부 스키마의 모든 열에 `←`를 달 수 있는가 | 외부 스키마의 열 항목 |
| 4 | 모든 제약·파생·계약 조항에 지키는 자리가 있는가 | 보장 위치표 |
| 5 | 모든 c에 연산 계약이 있는가 | 추적표의 계약 열 |
| 6 | 모든 q가 답을 받았거나 가정으로 등록되었는가 | 가정 목록(부록 B) |
| 7 | 예제 데이터를 넣으면 외부 스키마가 기대한 값을 내는가 | 인구 왕복 기록(손으로 먼저 낸 기대값과 함께) |
| 8 | 규칙을 어기는 데이터를 넣으면 지키는 자리가 거부하는가, 그리고 **그 규칙 때문에** 거부하는가 | 반례 시험 기록(거부 이유 포함) |

8번의 마지막 구절은 실습 P15를 만들며 실제로 겪은 일에서 왔습니다. 엉뚱한 제약에 걸려 거부된 시험은 그 규칙을 시험하지 않은 것과 같아요.

### 단계별 점검

**씨앗과 원장** (7장)

| 질문 | 어디서 확인 |
| --- | --- |
| 받은 자료를 모두 자료 목록에 올렸는가 | 원장의 자료 목록 |
| 원장 줄마다 출처와 근거 수준이 있는가 | 원장 본문 |
| 씨앗을 고쳐 쓰지 않고 해석을 t나 q로 남겼는가 | 원장 본문 |
| 연산의 빈도를 물었는가(모르면 q) | C 칸, Q 칸 |
| 한 줄에 둘을 적은 곳은 없는가 | "그리고" 검사 |
| 씨앗에 맞는 설계 전략을 골랐는가 | 7장 전략 표 |

**개념 스키마** (2장, 8장)

| 질문 | 어디서 확인 |
| --- | --- |
| 담화 세계에 넣은 것과 뺀 것을 적었는가 | 담화 세계 경계 |
| 표현·저장·메시지 형식이 섞이지 않았는가 | 개념화 원칙 |
| 응용 코드에만 있는 규칙이 없는가 | 100% 원칙 |
| 참조 방식이 시간이 지나도 바뀌지 않는가 | 개체 유형의 참조 방식 |
| 사실 유형이 기본 사실인가(뜻을 잃지 않고 쪼갤 수 있는 곳은 없는가) | CSDP 1·4단계 |
| 인구와 반례 인구로 제약을 담당자와 확인했는가 | CSDP 2·7단계 |
| 계산되는 것을 사실 유형으로 두지 않고 파생 규칙으로 두었는가 | 파생 규칙 |
| 정적 규칙과 동적 규칙(상태 전이)을 모두 적었는가 | 제약 목록 |
| 외부 스키마가 묻는 과거(이력)를 개념 스키마가 담고 있는가 | 9장 시점 질문 |

**외부 스키마** (3장, 9장)

| 질문 | 어디서 확인 |
| --- | --- |
| 이용자와 목적의 짝마다 외부 스키마가 있는가 | 이용자 목록 |
| 다섯 항목(이용자·내용·모양·파생 규칙·갱신 의미)을 모두 적었는가 | 외부 스키마 정의 |
| 쓰기를 받는다면 번역이 하나로 정해지는가 | 갱신 의미 결정표 |
| 가림(권한)과 시점(언제 기준)을 적었는가 | 가림·시점 항목 |
| 화면 꾸밈과 외부 스키마를 구분했는가 | 모양 항목 |

**관점 통합** (10장)

| 질문 | 어디서 확인 |
| --- | --- |
| 통합 순서와 우선순위를 정했는가 | 사전 통합 |
| 이름 충돌(동음이의·이음동의)과 구조 충돌(유형·종속·키·행위)을 근거와 함께 적었는가 | 충돌 표 |
| 맞추기 결정마다 근거와 남는 질문이 있는가 | 맞추기 표 |
| 다른 맥락을 억지로 합치지 않고 계약으로 남길 곳을 정했는가 | 경계 결정 |
| 완전성·적절성·정확성·최소성·이해 용이성을 점검했는가 | 품질 점검 표 |

**계약** (5장, 11장)

| 질문 | 어디서 확인 |
| --- | --- |
| 경계마다 계약이 있는가 | 경계 목록 |
| 다섯 겹(구조·의미·행위·품질·진화)을 모두 채웠는가, 해당이 없으면 이유를 적었는가 | 계약 양식(부록 C) |
| 실패마다 상태 변화와 다시 시도를 적었는가 | 실패표 |
| POST 같은 멱등이 아닌 연산의 재요청을 정했는가 | 행위 겹 |
| 기계용 명세가 담지 못하는 약속을 산문으로 적고 번호로 이었는가 | 명세와 산문 계약 |
| 공개 API를 선언하고, 약속하지 않는 동작을 밝혔는가 | 진화 겹 |
| 소비자 계약을 모았는가 | 소비자 계약 목록 |

**내부 스키마** (4장, 12장)

| 질문 | 어디서 확인 |
| --- | --- |
| 사상 규칙을 적용했고, 하위 유형 소속이 바뀌는 곳은 따로 다뤘는가 | 사상표 |
| 작업 부하 표의 모든 줄에 결정이 있고, 모든 인덱스가 어떤 줄에 기대는가 | 작업 부하 표, 결정 기록 |
| 결정 기록마다 다시 볼 조건이 있는가 | 결정 기록 |
| 같은 사실을 두 곳에 두었다면 누가 맞추는지 적었는가 | 보장 위치표 |
| DB 제약으로 못 거는 규칙에 감시 질의를 두었는가 | 보장 위치표 |
| DB 판마다 보장 범위가 다른 곳(예: 트리거가 INSERT에만 걸림)을 확인했는가 | 반례 시험 |
