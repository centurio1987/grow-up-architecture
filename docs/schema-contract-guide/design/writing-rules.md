# 집필 규칙 — 세 층 스키마와 계약

본문을 쓰면서 정한 규칙을 모은 문서입니다. 장을 새로 쓰거나 고칠 때 이 문서를 먼저 봅니다. 구성은 `design/structure.md`가 정본이고, 이 문서는 문장·표기·검사 규칙의 정본입니다.

## 1. 목소리

- 퍼소나는 `ppangtolab-teacher`(빵토랩 선생님)를 따릅니다. 존댓말 설명체로, 합쇼체(`~합니다`)와 해요체(`~해요`)를 섞습니다. 같은 종결이 네 문장 넘게 이어지지 않게 합니다.
- 개념을 정의하면 바로 예를 듭니다. 그림·표·코드 없이 산문 문단이 세 개 넘게 이어지지 않게 합니다(`max_prose_run = 2`).
- 헷갈리기 쉬운 곳은 "여기서 헷갈리기 쉬운 포인트는 ~입니다" 꼴로 짚고 반례를 보입니다.
- 기억법은 인용 블록(`> ...`) 한 줄로 줍니다. 장마다 한두 개.
- 논증은 끝까지 씁니다. `성립해서`·`임을 알 수 있습니다`·`이를 반복 적용하면`·`자명합니다`로 끝내지 않습니다.
- 독자용 글에 집필 메모(“해당 없음”, “이 절은 생략”, “그림을 다시 그리면”)를 남기지 않습니다.

## 2. 장의 골격

각 장은 다음 순서를 기본으로 합니다.

1. `## n장 제목` 다음 첫 문단: 이 장을 마치면 할 수 있는 것(한두 문장)
2. 본문 절(`###`)들: 문제 상황 → 정의와 출처 → 바로 예와 그림
3. `### 헷갈리기 쉬운 곳`(번호 목록. 산문 속 `첫째·둘째`는 박자 검사에 걸리므로 쓰지 않음)
4. `### 잠깐 확인`(질문 한 문단 + 답 한 문단)
5. `### 스스로 점검하기`(2~3문제) + `#### 풀이`

접기(`<details>`)는 쓰지 않습니다. `publish-report`가 `<details>` 안의 표·코드를 상자 밖으로 꺼내 그려서, 접힌 풀이가 흐트러지는 것을 2026-11-17 시험 굽기로 확인했습니다.

부의 첫 장 파일만 `# 제n부 ...` 머리글을 가집니다.

## 3. 번호 체계

| 대상 | 표기 | 예 |
| --- | --- | --- |
| 원장의 칸 | 대문자 | T 용어, F 사실, V 보기 요구, C 연산, R 규칙, Q 미결 질문 |
| 원장의 줄 | 소문자 + 번호 | t1, f3, v2, c1, r2, q4 |
| 개념 스키마 | F(사실 유형) · R(제약) · D(파생 규칙) | F2', R3, D1 |
| 외부 스키마 | V | V1 내 예약 |
| 계약 | O(연산) · E(이벤트) | O1 예약하기, E1 예약 확정 |
| 계약 안의 조항 | pre · post · inv | pre2, post1, inv1 |
| 작업 부하 | W | W1 |
| 내부 결정 | IX(인덱스) · PT(분할) · MV(실체화 뷰) | IX1 |

원장은 씨앗마다 하나씩 생기므로 원장 줄 번호는 그 원장 안에서만 뜻이 있습니다. 7장의 「틈」 콘셉트 메모 원장을 제2부 내내 이어 쓰고(8~13장에서 v3·v4·q6·q7 등을 더함), 14~26장의 작은 예는 각자 다른 씨앗에서 원장을 새로 뽑습니다. 다른 장의 원장 줄을 가리킬 때는 "7장 원장의 q4"처럼 장을 붙입니다.

실습 문제는 자기 도메인 안에서 같은 체계를 새로 씁니다. 본문 「틈」의 번호와 섞이지 않도록, 문제 안에서 처음 쓰는 번호는 그 문제의 것입니다.

## 4. 출처와 사실

- 원전을 직접 보지 못하고 2차 자료로만 확인한 것은 그렇다고 적습니다. 리서치 문서(`research/2026-11-17-three-schema-and-contract.md`)의 확인 수준 표시를 따릅니다.
- 직접 인용(영어 원문)은 15단어 이하, 장마다 많아야 한 곳입니다. 나머지는 우리말로 풀어 씁니다.
- 원전에서 온 말과 이 가이드가 만든 말을 구분합니다. 이 가이드가 만든 것: 추출 원장과 여섯 칸, 근거 수준(관찰·진술·확인), 계약의 다섯 겹, 보장 위치표, 실제 계약, 외부 스키마의 다섯 항목, 갱신 의미 결정표.
- 수치는 계산해서 확인한 값만 씁니다. 설명용으로 지어낸 빈도·목표는 "가정"이라고 붙입니다. 실습 자료의 수치는 `verification/`의 스크립트 출력에서 옮깁니다.
- 실행하지 못한 것(PostgreSQL DDL, 계약 시험)은 실행하지 못했다고 적습니다.
- 버전·날짜는 조회일(2026-11-17) 기준임을 밝힙니다.

## 5. 글자와 도식

- `publish-report`의 동봉 서체에 없어 굽기 가드에 걸리는 글자를 쓰지 않습니다. 상자 선 문자(U+2500~U+257F: `─ │ ┌ ┐ └ ┘ ├ ┤ ═ ║`)와 `⊆ ∪ ⊂ ⋈ ∧ ∨ ∈ ∉`입니다. 2026-11-17에 글자마다 구워 확인했습니다.
- 한자(예: `小`)도 동봉 서체에 없어 걸립니다. 우리말로 씁니다.
- 써도 되는 것: `+ - |`, `→ ← ↔ ▼ ▶ ▲ ◀`, `≤ ≥ ≠ ∅ π σ ¬ ⇒ · … × ±`.
- `tools/check_glyphs.py`로 확인합니다.
- 도식은 ```text 블록에 그립니다.

## 6. 어휘

`scan_lexicon.py --voice ppangtolab-teacher`가 거는 표현을 쓰지 않습니다. 집필 중 실제로 걸린 것:

| 쓰지 않는 표현 | 대신 |
| --- | --- |
| 절차를 `밟다` | 거치다 |
| 손에 `쥐다`, 책임을 `쥐다` | 받다, 맡다, 정하다 |
| 칸이 `밀리다` | 옮겨지다 |
| 성립을 `서다`(주의: `서지`도 걸림) | 성립한다, 논문 정보 |
| `닿다`(도달·관련) | 이어지다, 접근하다 |
| 실행을 `돌다`·`돌리다` | 실행하다 |
| `깨지다` | 어기다, 어긋나다 |
| 분류를 `축`이라 부름 | 기준, 갈래 |
| 물건이 아닌 것을 `세우다` | 두다, 정하다 |
| 이해를 `드러나다`로 | 알 수 있다 |
| 승부 비유(`이긴다`) | 받아들여진다, 앞선다 |

관형격 `의`가 한 문장에 셋 넘게, 연결어미가 넷 넘게, 복합조사가 둘 넘게 겹치면 문장을 나눕니다.

### 알려진 오탐

- 명사 `사실`(fact)과 `사실상`을 양태부사로 셉니다. 이 가이드의 핵심어(기본 사실, 사실 유형)가 한 문장에 둘 이상 나오면 걸립니다. 문장을 자연스럽게 고칠 수 있으면 고치고, 고치면 뜻이 흐려지는 곳은 그대로 둡니다. 그래서 `사실상 계약` 대신 `실제 계약`이라는 이름을 씁니다.
