## 20장 양식·화면·보고서

이 장을 마치면 종이 양식이나 화면 시안, 집계 보고서를 칸 단위로 읽어 원장에 옮기고, 상향 전략으로 개념 스키마 조각을 만들 수 있어요. 칸의 **출처**(직접 적는 값인지, 다른 데서 옮겨 적는 값인지, 계산하는 값인지)를 가르는 일이 이 장의 핵심입니다.

### 양식에서 개념 스키마로: 오래된 생각

양식에서 데이터베이스 설계를 끌어내는 연구는 1980년대에 이미 있었습니다. Choobineh·Mannino·Nunamaker·Konsynski의 1988년 논문 「양식 분석에 기반한 전문가 데이터베이스 설계 시스템」(*IEEE Transactions on Software Engineering* 14권 2호)은 양식 모델과, 양식 인스턴스를 분석하는 전문가 시스템을 제안했어요. 논문 소개 페이지로 확인한 요지는 이렇습니다. 양식 필드마다 **출처**(origin), 계층(hierarchy), 다중성(cardinality)을 잡고, 관련 양식을 하나씩 병합해 개념 스키마를 만들어 갑니다. 규칙의 단계는 양식 고르기 → 개체 찾기 → 속성 붙이기 → 관계 찾기 → 다중성 찾기 → 무결성 제약 순서예요. 첫 단계는 업무에서 양식이 오가는 순서를 근거로 분석 순서를 정하고, 그 뒤 단계는 설계자와 대화하며 진행합니다.

같은 연구진의 1992년 논문은 업무 양식에서 함수 종속을 유도하는 방법을 다뤘다고 하는데, 이 논문은 검색 요약만 확인했어요. Batini·Ceri·Navathe의 1992년 책에 양식 분석을 다룬 장이 있다는 이야기도 있지만 이번에 확인하지 못했습니다.

8장에서 본 Halpin의 **데이터 유스케이스**도 같은 자리를 가리킵니다. 출력 보고서와 입력 양식이 CSDP 1단계의 가장 좋은 재료라고 했지요. 양식은 담당자가 매일 쓰는 것이라, 말로 읽어 달라고 하면 기본 사실이 쉽게 나옵니다.

### 칸의 출처를 가른다

양식을 읽을 때 칸마다 먼저 묻는 것이 출처예요. 같은 이름의 칸이라도 출처에 따라 개념 스키마에서 가는 곳이 달라집니다. 아래 갈래는 1988년 논문의 "출처" 개념을 이 가이드의 산출물에 맞춰 풀어 쓴 것입니다.

| 칸의 출처 | 뜻 | 원장 칸 | 개념 스키마에서 |
| --- | --- | --- | --- |
| 직접 적음 | 이 양식에서 처음 생기는 값 | F | 이 양식이 다루는 개체의 사실 유형 |
| 옮겨 적음 | 다른 기록에 이미 있는 값을 베낌 | F, T | 다른 개체를 가리키는 참조. 값 자체는 그 개체의 사실 |
| 계산함 | 다른 칸에서 계산 | F, R | 파생 규칙 D |
| 미리 인쇄됨 | 고르기만 함(체크 칸, 보기 목록) | T, R | 값 제약, 코드표 |
| 담당자 기입란 | 다른 사람이 나중에 적음 | V, C | 다른 이용자, 다른 연산 |

"옮겨 적음"이 가장 놓치기 쉽습니다. 신청서에 회원 등급을 체크하는 칸이 있다고 해서 등급이 **신청서의 사실**인 것은 아니에요. 등급은 회원의 사실이고, 신청서는 그것을 베껴 적었을 뿐입니다. 이 구분을 놓치면 4장에서 본 갱신 이상(같은 회원의 등급이 신청서마다 다르게 적힘)이 생겨요. 다만 그 시점의 등급을 **기록해 두려고** 적는 칸일 수도 있으니, 담당자에게 물어 확인합니다. 9장의 시점 질문과 같은 질문이에요.

### 「틈」의 종이 신청서

앱이 생기기 전 「틈」에서 쓰던 종이 신청서가 남아 있다고 합시다. 칸이 보이게 글자로 옮겼습니다.

```text
+------------------------------------------------------------------+
| 회의실 이용 신청서                                No. 2026-0412     |
| 신청일  2026 년 11 월 10 일                                         |
| 회원번호 [ M07 ]   이름 [ 김하나 ]   등급 (V)일반  ( )상주            |
| 회의실  (V)R1 6인   ( )R2 4인   ( )R3                               |
| 이용 일시  11 월 17 일   10:00 ~ 11:30      ※ 30분 단위로 적으세요    |
| 참석자  1. 이수민   2. 정다은   3. ________                          |
| 화상 장비  ( )사용  (V)미사용                                        |
| ---------------------------- 데스크 기입 --------------------------- |
| 접수 [ 이지원 (서명) ]    입실 확인 [ 10:02 ]    이용 시간 [ 90 ] 분  |
+------------------------------------------------------------------+
```

칸마다 출처를 가르면 이렇습니다.

| 칸 | 출처 | 원장 | 메모 |
| --- | --- | --- | --- |
| No. 2026-0412 | 직접 적음(일련번호) | t5, q13 | 이 번호로 예약을 부르나? 그러면 참조 방식 후보 |
| 신청일 | 직접 적음 | f14 | 예약을 만든 날. 앱의 확정 시각과 같은 뜻인가 |
| 회원번호, 이름 | 옮겨 적음 | f15 | 회원의 사실(F1). 신청서에는 회원번호만 있으면 됨 |
| 등급 체크 | 옮겨 적음 | q14 | 그때 등급을 기록하려는 것인가, 단순 베낌인가 |
| 회의실 R1 6인 | 미리 인쇄됨 | t6, f16 | 코드표(R1·R2·R3). "6인"은 회의실의 사실(F3) |
| 이용 일시 | 직접 적음 | f17 | F6. "※ 30분 단위로"는 규칙(R2) |
| 참석자 1·2·3 | 직접 적음, 반복 영역 | f18, q15 | 1:N(F11 손님 이름). 세 칸은 규칙인가 종이의 한계인가 |
| 화상 장비 | 미리 인쇄됨 | f19 | 19장의 F15와 같은 것 |
| 접수 서명 | 담당자 기입 | c6, f20 | 데스크의 접수 연산과, 누가 접수했는가 |
| 입실 확인 시각 | 담당자 기입 | f21 | 노쇼 판정(q2)의 재료가 될 수 있음 |
| 이용 시간 90분 | 계산함 | r15 | 끝 - 시작. D로 둠 |

몇 줄을 짚겠습니다.

**반복 영역은 1:N입니다.** 참석자 칸이 1·2·3으로 반복되는 것은 신청서 하나에 참석자가 여럿이라는 뜻이에요. 12장의 사상 규칙 6(다중값 속성 → 따로 표)에 해당하고, 10장에서 데스크 관점 B에서 왔던 F11(손님 이름)과 같습니다. 그런데 세 칸이라는 숫자는 조심해야 해요. 종이가 좁아서 세 칸이었을 수도 있고, 정말로 손님을 셋까지만 받는 규칙일 수도 있습니다. q15로 물어요.

**담당자 기입란은 다른 이용자입니다.** 점선 아래 "데스크 기입" 영역은 회원이 아니라 데스크 직원이 적는 곳이에요. 한 양식 안에 두 이용자가 있고, 각자 다른 시점에 다른 연산을 합니다. 회원은 신청하고(c1), 데스크는 접수하고(c6) 입실을 확인해요. 입실 확인 시각(f21)은 7장 원장의 q2(노쇼는 누가 무엇으로 판정하나)에 대한 실마리입니다. 앱이 생기기 전에는 데스크가 입실을 손으로 적었던 거예요.

**계산 칸은 저장하지 않습니다.** 이용 시간 90분은 10:00과 11:30에서 계산됩니다. 그런데 데스크가 손으로 적은 값이라 틀릴 수 있어요. 예전 신청서 묶음을 옮겨 넣을 일이 있다면, 적힌 이용 시간과 계산한 값이 다른 신청서가 몇 장인지 세어 보는 것이 21장 이후의 거친 자료 다루기와 이어집니다.

이 신청서에서 나온 개념 스키마 조각을 정리하면 다음과 같습니다. 8장 결과와 겹치는 것은 번호만 적었어요.

```text
기존과 같음   F1(회원 이름) · F3(회의실 정원) · F6(시작·끝) · F11(손님 이름) · F15(화상 장비 사용)
새로 생김     F16 예약 은 신청일 을 가진다                    (q13·f14 답에 따라 확정 시각과 합칠 수도)
              F17 예약 은 접수한 직원 을 가진다
              F18 예약 은 입실 확인 시각 을 가진다             (필수 아님)
파생          D5 이용 시간 = 끝 - 시작 (분)
질문          q13 신청서 번호 = 예약번호인가 · q14 등급 칸의 뜻 · q15 손님 세 명이 상한인가
```

### 화면 시안과 보고서

화면 시안도 같은 방법으로 읽습니다. 입력 칸은 양식의 칸과 같고, 목록 화면은 반복 영역과 같아요. 화면에는 양식에 없는 것이 하나 더 있습니다. **버튼**이에요. 버튼 하나는 대개 연산 하나(C)이고, 버튼이 비활성으로 그려진 조건은 그 연산의 사전조건(R)입니다. "취소" 버튼이 시작 시각이 지난 예약에서 흐리게 그려져 있다면, 17장에서 물었던 "시작한 뒤에도 취소할 수 있나"에 대한 화면 쪽의 답이에요.

보고서는 대개 **외부 스키마 하나**를 그대로 보여 줍니다. 월 청구서는 V3이고, 합계 행은 파생 규칙이에요. 보고서에서 특히 볼 곳은 세 군데입니다. 머리글의 날짜(언제 기준인가), 합계 행(무엇을 더했는가), 각주(어떤 예외가 있는가)예요. 각주는 규칙이 숨어 있는 자리라서, "※ 노쇼는 이용으로 처리합니다" 같은 한 줄이 원장의 r 한 줄이 됩니다.

### 이 형식이 빼먹기 쉬운 것

| 빠지기 쉬운 것 | 이유 | 채우는 질문 |
| --- | --- | --- |
| 규칙의 이유 | 양식은 칸만 있고 설명이 없음 | "이 칸은 왜 있나요? 비우면 어떻게 되나요?" |
| 상태 변화 | 양식은 한 순간의 기록 | "이 신청서는 접수 뒤 어떻게 되나요? 취소하면?" |
| 쓰기의 뜻 | 화면 칸을 고치면 무엇이 바뀌는지 없음 | 9장의 갱신 의미 결정표로 따짐 |
| 빈 칸의 뜻 | 비어 있는 칸이 "없음"인지 "모름"인지 | "이 칸이 비어 있으면 무슨 뜻인가요?" |
| 종이의 한계와 규칙의 구분 | 칸 수, 칸 길이 | "세 칸은 규칙인가요, 종이가 좁아서인가요?" |

### 헷갈리기 쉬운 곳

1. 양식 하나가 개체 하나는 아닙니다. 신청서 한 장에 예약·회원·회의실·손님이 함께 들어 있어요. 1988년 논문의 단계가 "개체 찾기"부터 시작하는 것도 양식과 개체가 같지 않기 때문입니다.
2. 미리 인쇄된 보기는 값의 목록이지 규칙의 전부가 아닙니다. 회의실 보기가 R1·R2·R3이라고 해서 회의실이 영원히 셋은 아니에요. 보기 목록은 코드표로 옮기고, 목록이 바뀌는 절차(누가 회의실을 더하나)를 q로 남깁니다.
3. 양식 칸의 이름을 그대로 쓰면 이음동의어가 생깁니다. 신청서에 적힌 "이용 일시", 앱에 적힌 "예약 시간", 청구서에 적힌 "사용 시간"이 같은 것을 가리키는지 10장의 비교 단계에서 맞춰야 해요.

### 잠깐 확인

신청서의 "등급 (V)일반" 칸은 원장에 무엇으로 적었고, 담당자가 "청구할 때 그때 등급을 쓰려고 적었다"고 답하면 개념 스키마는 어떻게 바뀌나요?

처음에는 옮겨 적은 값이라 q14로 남겼어요. 담당자의 답이 그렇다면 이 칸은 단순한 베낌이 아니라 "신청 시점의 등급을 기록한다"는 뜻이 됩니다. 그런데 9장에서 이미 등급 이력(F2')을 두었으므로, 예약 시점의 등급은 F2'에서 예약 날짜로 찾을 수 있어요(D4). 같은 등급을 신청서에 또 적으면 두 값이 어긋날 수 있으니, 새 사실 유형을 만들지 않고 D4로 답하는 편이 낫습니다. 다만 청구 규칙이 "월말 기준 등급"(13장의 가정)이라면 신청 시점 등급은 청구에 쓰이지 않으므로, 그 사실을 담당자와 다시 맞춰야 해요.

### 스스로 점검하기

1. 「틈」의 월 청구서 보고서에 "※ 상주 회원의 초과 시간은 다음 달 무료 시간에서 먼저 뺍니다"라는 각주가 있다고 합시다. 이 각주가 원장과 개념 스키마에 무엇을 더하는지 적어 보세요.
2. 신청서 묶음 200장을 데이터로 옮기려 합니다. 칸의 출처 갈래를 써서, 옮길 때 그대로 넣을 칸과 계산해서 대조할 칸과 버릴 칸을 나눠 보세요.

#### 풀이

1. 원장에 `r16 상주 회원의 초과 시간은 다음 달 무료 시간에서 먼저 뺀다`(출처: 청구서 각주, 근거: 진술)를 더하고, "초과가 다음 달 무료 시간보다 크면 남는 것은 어떻게 하나?"를 q로 남깁니다. 개념 스키마에는 달을 넘어가는 값이 생기므로 `회원 은 월 에 이월 분 을 가진다` 같은 사실 유형이나, 앞 달의 초과에서 계산하는 파생 규칙이 필요합니다. 파생으로 두면 D2(초과 분)가 앞 달 값에 기대게 되어 계산이 달마다 이어지므로, 저장할지 파생할지 12장의 작업 부하와 함께 정합니다. 13장의 V3 결과(상주 회원의 초과가 0)도 이 규칙이 생기면 다시 계산해야 합니다.
2. 직접 적은 칸(신청서 번호, 신청일, 이용 일시, 참석자, 화상 장비, 접수 서명, 입실 확인 시각)은 그대로 넣습니다. 옮겨 적은 칸 가운데 회원번호는 넣되 회원 표에 있는지 대조하고, 이름과 등급은 회원 쪽 값과 대조만 하고 신청서의 사실로 넣지 않습니다(어긋나는 장 수를 셉니다). 계산 칸인 이용 시간은 넣지 않고, 시작·끝에서 계산한 값과 대조해 다른 장을 표시합니다. 미리 인쇄된 회의실 정원 "6인"은 신청서마다 넣지 않고 회의실의 사실로 한 번만 둡니다.

이어지는 실습: P08 동네 학원(영수증 양식과 출석부).
