## 1. 미흡 항목

### E1 모순 없음 [MUST] — 2건, 이 편에서 가장 중요한 문제입니다

**E1-a. 최소 조건 5번은 [선택]인데, 어기면 Strategy 가 아니게 됩니다.**
- 155: "`[필수]` 가 하나라도 빠지면 Strategy 가 아니고, `[선택]` 은 갖추면 좋은 구조예요."
- 164: "5. [선택] 전략끼리 서로를 설치하지 않습니다 — … 이런 코드가 보이면 비교 절의 State 기준으로 다시 판정합니다."
- 189: "그런 코드가 있으면 State 쪽이고"

반례로 확인했습니다. 첫 상태는 생성자로 받고 전이는 `light = light.press(this)` 처럼 상태 객체가 정하는 코드를 봅니다.
- 1번(공통 타입), 2번(필드가 인터페이스 타입이고 타입 검사가 없음), 3번(구체 객체가 Context 밖에서 만들어지고 Context 안에 분기가 없음)을 모두 만족합니다.
- analyzer(design-pattern-analyzer) 계약대로라면 판정은 "Strategy, 5번 보강 권장"입니다.
- 그런데 비교 절(189)은 같은 코드를 State 로 봅니다.

어떻게 고칠지(권장안):
- 5번을 3번에 합칩니다. 161 판정문 끝에 "요청을 처리하는 코드(Context 메서드와 ConcreteStrategy 연산 모두)가 Context 의 전략 참조에 다른 구현 객체를 넣거나 다음에 쓸 구현을 돌려주지 않습니다"를 더합니다.
- 162 반례에 한 문장을 더합니다: "`state = state.pay(this)` 처럼 구현 객체가 다음 구현을 돌려주면, 첫 전략을 밖에서 받았더라도 State 입니다."
- 164를 지우고 6번을 5번으로 바꿉니다.
- 본문 어디에도 "5번"·"6번" 참조가 없어서(grep 확인) 30 "필수 조건 세 가지", 63 "2·3번", 642·681 "1~3번"은 고칠 필요가 없습니다.
- 이렇게 하면 Context 가 정하는 전이는 3번의 기존 문구에, 상태 객체가 정하는 전이는 새 문구에 걸립니다. "누가 정하나" 하나만으로 가르지 않으므로 잠정 결정과도 맞습니다.

**E1-b. Command 구분 기준을 적용하면 본문의 `RejectedExecutionHandler` 사례가 Strategy 에서 밀려납니다.**
- 186·249: "구현 객체들이 같은 질문에 같은 종류의 값을 돌려주고 Context 가 그 값을 곧바로 자기 계산에 쓰는지입니다. 그렇다면 Strategy 이고, 구현마다 서로 다른 일을 하나씩 담아 두었다가…"
- 662는 `rejectedExecution(Runnable, ThreadPoolExecutor)` 를 Strategy 구조로 듭니다.
- 공식 문서로 확인한 시그니처는 `void rejectedExecution(Runnable r, ThreadPoolExecutor executor)` 입니다. 돌려주는 값이 없고, 정책마다 하는 일(예외 던지기·호출한 스레드에서 실행·버리기)도 다릅니다.
- 그래서 249 기준대로 읽으면 이 사례는 오히려 Command 쪽으로 기웁니다.

어떻게 고칠지:
- 186·249 기준을 이렇게 바꿉니다: "Context 가 받은 구현 객체를 자기 요청을 처리하는 도중에 그 자리에서 호출하는가(반환값 유무 무관), 요청 하나를 객체로 만들어 큐·이력·다른 실행기에 두었다가 나중에 실행하는가."
- 186 "얻는 것" 칸의 "결과를 바로 계산에 씀"도 같이 고칩니다.
- 252~260 도식에 반환값이 없는 전략 한 줄(`CallerRunsPolicy.rejectedExecution(r, pool)` → 그 자리에서 실행)을 더하면 기준이 도식으로도 보입니다.

막지는 않지만 같이 고치면 좋은 곳: 185 "얻는 것: 실행 중 교체"와 247 "실행 중에 전략을 바꿀 수 있고"는 [선택] 4번과 결이 어긋납니다. "설치 방식에 따라 실행 중 교체도 가능(최소 조건 4번)"으로 낮추면 됩니다.

## 4. 사실 확인에서 걸린 것
- **WebFetch 로 직접 확인한 링크 8건(모두 주장과 일치):**
  - Spring `ResourceEditor`: "Delegates to a ResourceLoader … by default using a DefaultResourceLoader"와 생성자 3종, 7.0.9
  - Spring `ResourceLoader`: "Strategy interface for loading resources", 구현 클래스에 FileSystem·ClassRelative 포함
  - refactoring.guru Strategy in Java: `Comparator#compare()` called from `Collections#sort()`, 식별 문장 "a method that lets a nested object do the actual work, as well as a setter…"
  - refactoring.guru State: "states may be aware of each other and initiate transitions … strategies almost never know about each other"
  - Java `FunctionalInterface`: "the compiler will treat any interface meeting the definition … regardless of whether or not a FunctionalInterface annotation is present"
  - `ThreadPoolExecutor`: execute 가 rejectedExecution 호출, 네 정책, 기본값 AbortPolicy, `setRejectedExecutionHandler`
  - `RejectedExecutionHandler`: 반환형 `void` — E1-b 의 근거
