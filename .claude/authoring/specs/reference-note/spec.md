# 참고 문서 — 항목별 작성 방법

> **층: L2 (글 명세)** · 적용 voice: `ppangtolab-teacher` · 캔버스: `paths.json` 의 `templates.reference-note-canvas` · 산출 위치: `dirs.reference`/<슬러그>/
> 출처: 파일럿 검토(2026-09-21 유저 지적) + `gof-guide`·`analysis-guide` 1.4.0 의 「원서를 다루는 법」(PG30·PG31) + AG4.
> 문체(존댓말·도식·산문 연속 상한·기억법 등)는 voice 소유라 여기 쓰지 않는다.

## 이 글은 무엇인가

가이드가 기대는 **주제 밖 사전 지식**을 원서 없이 읽히게 푸는 짧은 문서다. 가이드 두 트랙의 명세는 이렇게 말한다 —
본문이 원서의 개념·논의에 기대야 할 때, 그 가이드의 주제 안이면 그 자리에서 풀고, **주제 밖이면 참고 문서를 쓰고 내부 링크로 잇는다**(PG30).
이 명세는 그 참고 문서의 골격이다.

> "가이드에서 해당 내용을 참조하는 것이 주제를 벗어나지만, 사전 이해가 필요하다면, 별도의 가이드나 참고 문서를 작성해서 내부 참조를 하도록 만들어라." — 유저(2026-09-21)

**무엇을 쓰는가.** 여러 가이드가 같은 사전 지식을 전제할 때다. Strategy 가 Flyweight 의 내재 상태를, Account 가 복식부기의 차변·대변을,
모든 분석 가이드가 DDD 전술 용어를 전제한다. 가이드마다 그것을 풀면 주제를 벗어나고 열 번 되풀이하면 어긋나기 시작한다.

**무엇을 쓰지 않는가.** 패턴의 판정(최소 조건)·비교·구현은 가이드의 몫이다(RN7). 참고 문서가 그것을 싣는 순간 가이드와 두 벌이 된다.
원서를 요약해 옮기는 것도 아니다 — 독자가 필요한 만큼의 개념을 **예와 함께** 세우는 것이다.

```text
가이드 본문 ──(주제 밖 사전 지식)──▶ 참고 문서 ──(가이드로 돌아가기)──▶ 가이드 본문
                                      ├ 이 문서가 답하는 것
                                      ├ 개념(### 개념마다 정의 + 예)
                                      ├ 개념 사이의 관계(도식 1개)
                                      ├ 가이드로 돌아가기(내부 링크)
                                      └ 참고 자료
```

### 첫 후보 네 편(예시 — 확정은 집필 카드가 한다)

| 슬러그 | 답하는 것 | 보내는 가이드 |
| --- | --- | --- |
| `gof-vocabulary` | GoF 원서가 여러 패턴에 걸쳐 쓰는 어휘 — 내재/외재 상태 · Invoker/Receiver · 정적/동적 디스패치 · 클래스 패턴/객체 패턴 · 컴파일 시점/실행 시점 결합 | GoF 트랙 전부(비교 절에서 상대 패턴 개념이 필요할 때) |
| `ddd-tactical-terms` | Bounded Context · Aggregate · Aggregate Root · Entity · Value Object · id 참조 · 불변식 | 분석 트랙 전부(상황 설정 표, AG4) |
| `accounting-model` | Fowler 6장의 Account/Entry/Transaction/Posting Rule/Money 개념 지도 + 복식부기 기초(차변/대변 부호 규약 · 원장 · 전기 · 역분개 · knowledge level) | Account · Transaction · Posting Rule |
| `observation-model` | Fowler 3장의 Quantity/Unit/Conversion Ratio/Compound Unit/Measurement/Observation/Range 개념 지도 | Quantity · Range · Measurement · Observation |

## 산출 위치와 버저닝

가이드와 같은 규약이다. 참고 문서 한 편이 **폴더 하나**를 갖는다.

```text
pattern-guide/reference/<슬러그>/        ← dirs.reference, 슬러그는 kebab-case
  <슬러그>-ref_v<major>.<minor>.<patch>.md     ← 본문(최신은 버전이 가장 높은 파일)
  <슬러그>-ref_v<major>.<minor>.<patch>.html   ← 렌더 산출물
  diagrams/  ← 도식 소스와 렌더 이미지
```

- **머리말(frontmatter)** 에 `title` · `slug` · `spec: reference-note` · `spec_version` · `version` · `status`(`draft` · `published` · `legacy`) · `date` ·
  **`serves`**(이 문서를 링크하는 가이드 슬러그 목록)를 둔다. `serves` 는 `## 가이드로 돌아가기` 의 링크 대상과 맞아야 한다(RN4).
- 버전 기준 · `draft` 동안 제자리 편집 · 이전 판본 보존 · 최신 포인터 · `spec_version` 일치 — 가이드 공유 블록 「산출 위치와 버저닝」과 같다.
  가이드가 참고 문서를 링크할 때도 최신 파일명을 쓰고, `check-guides --pointers` 가 낡은 링크를 잡는다.

## 절별 작성법

### 제목 + 한 줄 답 (`title`)

`# {제목} — {한 줄 답}`. 제목은 이 문서가 다루는 개념군의 이름(「DDD 전술 용어」 · 「복식부기와 회계 모델」), 뒤는 이 문서가 주는 답을 한 줄로.

### 이 문서가 답하는 것 (`answers`)

- **어느 가이드가 어떤 사전 지식 때문에** 독자를 여기로 보내는가를 2~4문장으로. 머리말 `serves` 와 일치한다.
- **다루지 않는 것**을 한 문장으로 못 박는다 — "패턴이 성립하는 조건과 코드는 각 가이드에 있습니다"(RN7).

### 개념 (`concepts` · `### {개념}`)

- `### {개념}` 이 **2개 이상**이다(RN2). 헤딩은 개념 이름 그대로(영문 용어는 원어 유지).
- 개념마다 **정의 한 문단 + 구체 예 1개**. 예는 값·상황으로("현금 계정에 +100,000 이 적히면 …"). 흔한 오해는 선택이다.
- **정의는 원서를 펴지 않아도 선다**(RN1). "Evans 가 그렇게 적었다"로 끝내지 않고 **왜 그 구분이 필요한지**를 쓴다. 근거 링크는 그 설명 옆에.
- 원서 위치 지시자(`그림 n.n` · `§n.n` · `n장`)는 `(근거: …)` 괄호와 참고 자료에만 쓴다 — 가이드의 PG30 과 같은 규칙이고 검사기가 같은 방식으로 막는다.

### 개념 사이의 관계 (`relations`)

- 도식 **1개**(viz 이미지 또는 text 도식)와 설명(RN3). 도식에 나오는 이름은 `### {개념}` 헤딩과 1:1 — 정의 없는 이름이 그림에 있으면 미흡.
- 관계는 "A 가 B 를 여럿 갖는다" 처럼 다중도·방향까지 말로 쓴다. 그림 번호로 대신하지 않는다.

### 가이드로 돌아가기 (`back`)

- **어느 가이드의 어느 절이 이 문서의 어느 개념을 쓰는가**를 목록으로. 링크는 실제 가이드 파일(최신 버전 파일명)로의 상대 링크이고 검사기가 해소한다(RN4).
- 아직 안 쓰인 가이드(집필 예정)는 올리지 않는다 — 링크가 깨진다. 그 가이드가 발행될 때 여기에 한 줄 더한다(patch 판본).

### 참고 자료 (`refs`)

- 원전을 맨 앞에 장·절까지(RN6). 본문에서 출처로 단 링크를 전부 모으고, 항목마다 본문의 무엇을 뒷받침하는지 한 구절.

## 원칙 (`spec.json` `principles[]`)

| 코드 | 수준 | 축 | 한 줄 |
| --- | --- | --- | --- |
| RN1 | MUST | evidence | 자립성 — 원서 위치 지시자는 근거 괄호·참고 자료에만(검사기) |

## 채점 규약

- 기계 검사(`check-guides --all`)는 참고 문서에도 돈다 — 헤딩 골격 · 버저닝 · 상대 링크 · RN1 의 위치 지시자 · 문체 검사 · 이미지 해소.
  `--compile` · `--run` 은 대상이 아니다(구현 펜스가 없다).
- 산문 연속 상한(voice V1)은 `golden.py measure` 값으로 판정한다(가이드와 같다).
- 사실 주장은 채점이 원문과 대조한다. 외부 모델 비평은 쓰지 않는다(2026-09-20 유저 결정).
- 게이트는 최대 3라운드, 자동 통과 없음. 통과하면 `dirs.gate_results` 에 한 줄(`spec: reference-note`).
