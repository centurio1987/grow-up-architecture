# 디자인 패턴 가이드 작성 Skill

이 skill은 하나의 디자인 패턴에 대한 가이드 문서를 표준 양식에 맞춰 작성하기 위한 절차와 템플릿을 제공한다.

## 산출물

- 파일 형식: Markdown(`.md`)
- 파일 위치: `/Users/centurio/design-pattern-guide/{패턴_영문명_kebab-case}.md`
  - 예: `singleton-pattern.md`, `factory-method-pattern.md`
- 파일 1개 = 디자인 패턴 1개. 여러 패턴을 요청받으면 문서를 패턴별로 분리해 생성한다.

## 템플릿

표준 양식은 같은 폴더의 `template.md`에 정의되어 있다. 새 가이드를 작성할 때는 반드시 `template.md`를 먼저 읽고, 그 구조와 섹션 순서를 그대로 따른다.

템플릿이 정의하는 필수 섹션(순서 고정):
1. 제목 + 한 줄 요약
2. 상세 설명
3. 디자인 패턴을 충족하는 최소 조건
4. 사례를 통한 예시
5. 어떨 때 사용하나
6. 장점과 단점, 한계점
7. 정보 표 (언어 의존성, 활용성(1점~5점) 등)
8. Class Diagram (Mermaid `classDiagram`)
9. 참고 자료

원본 참조 문서는 `/Users/centurio/design-pattern-guide/디자인 패턴 가이드 템플릿 작성을 위한 참조 문서.md` 이며, 이 파일에 정의된 섹션 명칭은 그대로 유지한다.

## 작성 절차

1. **요청 파악**: 사용자가 지정한 디자인 패턴 이름과, 추가 요구사항(예시 언어 지정, 분량 등)을 확인한다. 패턴이 모호하면 사용자에게 한 번 확인한다.
2. **템플릿 로드**: `skills/design-pattern-guide/template.md`를 Read 한다.
3. **본문 작성**: 템플릿의 모든 섹션을 빠짐없이 채운다. 빈 섹션(예: "TBD")을 남기지 않는다.
   - "상세 설명"은 의도(Intent), 문제, 해결 방식이 모두 드러나야 한다.
   - "최소 조건"은 3개 이상 항목을 명확한 판정 기준 형태로 작성한다.
   - "사례를 통한 예시"는 최소 2개: ① 직접 작성한 미니멀 예시, ② 실제 라이브러리/프레임워크에서의 사용 사례.
   - "정보 표"는 표 형식을 유지하고 `활용성(1점~5점)` 항목은 반드시 점수와 1줄 근거를 포함한다.
   - "Class Diagram"은 Mermaid `classDiagram` 코드 블록으로 작성하며, 다이어그램 아래에 각 클래스의 역할(Role) 설명을 덧붙인다.
4. **코드 예시 규칙**:
   - 언어가 지정되지 않으면 Java 또는 TypeScript 중 패턴 설명에 더 적합한 쪽을 고른다.
   - 예시 코드는 그대로 실행 가능한 수준으로 자기-완결적이어야 한다(불필요한 import는 생략 가능).
5. **검증**: 작성 직후 다음을 확인한다.
   - 템플릿의 모든 ## 헤더가 문서에 존재하는가
   - "정보 표" 행이 누락되지 않았는가 (특히 `언어 의존성`, `활용성`)
   - Mermaid 블록이 ```mermaid ... ``` 로 닫혀 있는가
   - `{중괄호}` 형태의 플레이스홀더가 남아 있지 않은가
6. **결과 공유**: `mcp__cowork__present_files`로 생성된 가이드 파일을 사용자에게 공유한다.

## 파일명 규칙

- 영문 패턴명을 kebab-case로 변환한 뒤 `-pattern.md` 접미사를 붙인다.
  - Singleton → `singleton-pattern.md`
  - Factory Method → `factory-method-pattern.md`
  - Chain of Responsibility → `chain-of-responsibility-pattern.md`
- 사용자가 한글 파일명을 명시적으로 요청하면 그에 따른다.

## 톤 & 스타일

- 한국어로 작성하되, 패턴/역할/클래스 등의 전문 용어는 영문 원어를 괄호로 병기한다(예: 단일체(Singleton), 추상 팩토리(Abstract Factory)).
- 단정적·교과서적 문체. 1인칭 사용 금지.
- 불릿은 의미가 분명할 때만 사용하고, "상세 설명"과 "어떨 때 사용하나"는 가능하면 산문형으로 작성한다.
- 이모지는 사용하지 않는다.

## 하지 말 것

- 템플릿의 섹션을 임의로 추가/삭제/순서 변경하지 않는다. 보조 섹션이 필요하면 기존 섹션 내부에 `###` 하위 헤더로 둔다.
- "정보 표"에서 `언어 의존성`, `활용성(1점~5점)` 항목을 누락하지 않는다.
- 빈 코드 블록(```\n```)을 남기지 않는다.
