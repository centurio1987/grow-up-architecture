디자인 패턴 가이드 인덱스

GoF(Gang of Four) 23개 디자인 패턴의 한국어 가이드 모음. 각 문서는 authoring-kit 명세 gof-guide(분석 패턴은 analysis-guide)가 정한 골격을 따른다.

Creational Patterns (생성 패턴)

객체 생성 메커니즘을 다루며, 상황에 맞는 객체 생성 방식을 제공한다.

패턴한 줄 요약가이드

Abstract Factory (추상 팩토리)관련된 제품군(family)을 일관되게 생성하는 인터페이스 제공abstract-factory-guide_v1.0.0.md
Builder (빌더)복잡한 객체의 생성 과정을 단계적으로 분리builder-guide_v1.0.0.md
Prototype (프로토타입)미리 만들어 둔 견본을 복제해 새 객체를 얻음prototype-guide_v1.0.0.md

클래스와 객체를 더 큰 구조로 조합하는 방법을 다룬다.

패턴한 줄 요약가이드

Composite (컴포지트)부분-전체 계층을 같은 인터페이스로 다루고, 묶음의 답은 자식들의 답을 모아 만듦composite-guide_v1.0.0.md

객체 간 책임 분배와 상호작용 방식을 다룬다.

패턴한 줄 요약가이드

Interpreter (인터프리터)문법 규칙 하나를 타입 하나로 세우고, 문장의 뜻을 트리에서 합성interpreter-guide_v1.0.0.md
Iterator (이터레이터)순회 위치를 집합 밖의 순회자에 들려, 내부 표현을 숨긴 채 원소를 차례로 내줌iterator-guide_v1.0.0.md

Memento (메멘토)되돌릴 상태를 통째로 떠서, 아무도 못 여는 값으로 맡김memento-guide_v1.0.0.md

State (상태)상태마다 객체를 두고 요청을 위임하며, 그 상태 객체가 실행 중에 바뀜state-guide_v1.0.0.md
Strategy (전략)알고리즘군을 캡슐화하고 런타임 교체strategy-guide_v1.1.0.md

분석 패턴 (Analysis Patterns)

Martin Fowler 『Analysis Patterns』(1997)의 분석 패턴이다. GoF 가 구현 설계의 반복을 다룬다면 이쪽은 도메인을 개념으로 모델링하는 단계의 반복을 다룬다 — 사람·조직·관계·측정·회계처럼 업무 시스템의 뼈대가 되는 구조다. 계열별 분류와 패턴 간 의존 흐름은 분석 패턴 인덱스에 있다.

패턴한 줄 요약가이드
Party (당사자)사람과 조직을 한 이름으로 받아 공통인 것을 그 한 자리에 모음party-guide_v1.0.0.md
Accountability (책임 관계)두 당사자를 잇는 관계를 칸이 아니라 개념으로 세워 종류·기간을 닮accountability-guide_v1.0.0.md
Knowledge Level (지식 수준)사실을 해석하는 규칙을 사실과 다른 층에 인스턴스로 세움knowledge-level-guide_v1.0.0.md
Quantity (수량)값과 단위를 묶어 단위 안전 연산 제공quantity-guide_v1.1.0.md
Range (범위)두 끝과 「그 끝을 포함하는가」를 한 값에 담아 경계 판정을 한 곳에 모음range-guide_v1.0.0.md
Measurement (측정)값 하나를 대상·항목과 묶어 기록 한 건으로 세운다measurement-guide_v1.0.0.md
Observation (관찰)대상에 대한 사실을 값의 종류와 상관없이 한 층으로 다룬다observation-guide_v1.0.0.md
Account (계정)잔액을 항목(Entry)의 합으로 도출account-guide_v1.1.0.md
Transaction (거래)함께 적어야 할 기록을 한 묶음으로 만들고, 만드는 자리에서 합을 0 으로 맞춤transaction-guide_v1.0.0.md
Posting Rule (전기 규칙)무엇에 반응해 얼마를 어느 계정에 적을지를 규칙 하나가 쥔다posting-rule-guide_v1.0.0.md

분석 패턴의 「최소 조건」은 코드 구조가 아니라 개념적 책임 분리를 기준으로 판정한다 — 같은 모델이 상속·인터페이스·값 객체·규칙 엔진 등 여러 형태로 실현되기 때문이다.

빠른 비교가 자주 필요한 페어

각 가이드의 「비슷한 패턴·안티패턴과의 차이」 절에서 더 자세히 다룬다.

  • Factory Method ↔ Abstract Factory: 생성을 제품을 쓰는 클래스 자신의 하위 클래스에 미루는가(제품 한 종류) vs 별개의 팩토리 객체에 미루는가(서로 맞물리는 제품군)
  • Strategy ↔ State: 구현 객체들이 같은 계산의 대안인가 vs 객체가 오가는 상태인가 — 요청 처리 결과로 다음 구현이 정해지는 코드가 있는지는 먼저 보는 곳이고, 밖에서 온 선택으로 갈아 끼워도 State 일 수 있다
  • Adapter ↔ Decorator ↔ Proxy: 인터페이스 변환 vs 행위 추가 vs 접근 제어
  • Builder ↔ Abstract Factory: 조립 단계를 순서대로 부르고 마지막에 결과를 꺼내는가 vs 호출 한 번에 완성된 제품을 받는가
  • Mediator ↔ Facade: 가운데 객체를 안쪽 객체들도 아는가 vs 바깥 Client 만 아는가 — 갈리는 것은 방향이다

참고 문서

가이드가 기대는 주제 밖 사전 지식을 원서 없이 읽히게 푼 문서다. 패턴의 판정·비교·구현은 싣지 않는다 — 그건 가이드의 몫이다. 가이드 본문이 필요한 자리에서 이 문서들을 내부 링크로 가리킨다.
